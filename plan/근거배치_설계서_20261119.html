근거 배치 — 1위 근거를 질문 바로 앞에

답변 모델에게 근거 3개를 줄 때, 지금은 1위 → 2위 → 3위 → 질문 순서로 넣는다. 작은 모델은 질문 바로 앞 내용을 더 잘 쓴다는 주장이 있어 골든셋으로 재 보았다. Qwen3-1.7B 는 정답 46 → 54 로 좋아졌지만, Mi:dm 은 그대로이고 Qwen3.5-4B 는 62 → 56 으로 나빠졌다. 그래서 이 배치를 모든 모델에 켜지 않고, config.yaml 에 적은 모델에만 켠다. 기본으로는 Qwen3-1.7B 하나만 적는다.

2. 배경 — 검색해 온 방법 검토

검색해 온 글은 2B 급 작은 모델의 RAG 정확도를 올리는 방법으로 두 가지를 들었다.

글의 주장검토결론
가장 관련도 높은 1위 근거를 맨 마지막(질문 바로 앞)에 둔다. 모델은 입력의 앞·끝은 잘 쓰고 가운데는 놓친다. "Lost in the Middle"(2023) 연구가 근거다. 다만 그 연구는 문서 10~30개짜리 긴 입력이었다. 우리는 짧은 근거 3개(2048 토큰 안)라 효과가 작을 것으로 봤지만, 재 보니 1.7B 에서는 뚜렷했다. 모델별로 채택
근거에 [문서1]·[문서2] 번호를 붙이고 문장마다 근거 번호를 달게 하면 환각이 70% 이상 준다. 번호 붙이기와 "마지막에 근거 번호" 지시는 이미 하고 있다(SYSTEM_PROMPT). "70%" 는 출처가 없다. 문장마다 번호를 강제하면 작은 모델이 지시문을 따라 적는 잡음이 늘 수 있다 (설계서 R9: 인용 강제형 지시문으로 정답률 83% → 50% 전례). 지금 그대로

3. 측정 방법

  • 문항: dataset/golden_pdf30.jsonl 골든 100문항 (sample PDF 30건)
  • 인덱스: dist/simplerag (SIMPLERAG_HOME), 근거 3개(top_k: 3), 리랭커 후보 10개
  • 도구: bench/ragas_golden.py collect --ctx-order rank|reverse|reverse_keepnum — 이번에 넣은 실험용 옵션. 제품 코드는 그대로 두고, 프롬프트 조립 함수만 바꿔 끼운다. 검색·리랭킹 결과는 같다(1.7B 두 실험의 근거 문서 100/100 일치).
  • 채점: bench/score_rule.py 규칙 지표 — 답에 핵심어(must)가 모두 들어 있으면 정답. 판정 LLM(RAGAS)은 쓰지 않았다.
  • 짝 비교: 같은 문항을 한쪽만 맞힌 개수(새로 맞힘 / 놓침)와 McNemar 정확검정 p 값
  • 실험 폴더: results/ragas_golden/ord_*_1118(1.7B), ord_*_1119(Mi:dm · Qwen3.5-4B)

  • 놓친 10문항 가운데 약 4개는 채점 규칙 탓이다. 역순 답이 더 짧고(평균 156 → 136자) 근거 글을 덜 옮겨 적어, 뜻은 맞아도 핵심어 글자가 빠졌다(예: "1년에 1회" 대신 "매년 1회", "10인 이상" 대신 "10명 이상"). 나머지 6개는 실제로 내용 하나를 빠뜨리거나 틀렸다.

결론을 고친다: 1.7B 에서도 이득이 질문 모양에 따라 달라, "좋아진다"고 말할 근거가 약하다. 규칙 채점은 답을 길게 옮겨 적을수록 유리해 짧아진 역순 답을 깎는 쪽으로 치우쳐 있으므로, 뜻으로 채점하는 판정(RAGAS Answer Correctness 등)으로 한 번 더 보고 켬/끔을 정한다. 0.1.7 은 켬으로 배포됐다.

4-6. 뜻 채점 — Claude 판정 RAGAS (2026-11-19)

규칙 채점이 긴 답에 유리하게 치우칠 수 있어, 4개 실험(골든 100 기존·역순, 일상어 100 기존·역순)의 답 400건을 Claude 판정자 8개가 나눠 판정했다 (bench/ragas_claude.py, 폴더 results/ragas_golden/claude_judge_ctx). 같은 문항의 두 답을 한 묶음에 A·B 로 섞어 넣어 어느 쪽이 역순인지 판정자는 모른다. RAGAS 4지표에 더해, 답이 정답의 핵심 사실을 모두 담고 어긋나지 않는지(뜻 정답, 표현이 달라도 뜻이 같으면 맞음)를 함께 판정했다.

골든 100rank46——0.7290.6620.8800.822
reverse_keepnum53+10 / −30.090.7350.6610.8800.822

  • 뜻으로 채점하면 두 세트 모두 역순이 낫다. 일상어 세트에서 규칙 채점은 32 → 28 이었지만 뜻 채점은 30 → 36 으로 방향이 뒤집혔다 — 4-5 에서 본 대로 역순 답이 짧아 핵심어 글자가 빠졌을 뿐 뜻은 맞은 경우가 많았다.
  • 두 세트를 합치면 +21 / −8, p=0.02 로 유의하다.
  • RAGAS F(근거 충실)·AR(질문 관련)은 차이가 없다(짝 부호 검정 p≈1). 지어내거나 엉뚱하게 답하는 정도는 같고, 답이 정답을 맞히는지만 달라졌다. CP·CR 은 두 배치의 근거가 같아 값이 같다(근거만 보는 지표).
  • 판정자는 Claude 한 종류다. 공용 판정 서버(qwen3.6-35b) 점수와는 섞어 비교하지 않는다.
결론(최종): 4-5 의 경고를 거둔다. 뜻으로 채점하면 Qwen3-1.7B 에서 역순 배치가 골든 · 일상어 모두 정답을 늘리고(합계 +21 / −8, p=0.02), 근거 충실도·질문 관련성은 그대로다. 0.1.7 의 기본 켬(reverse_context_models: [qwen3-1.7b-q4])을 유지한다.

4-7. 주의할 점

  • 같은 날 실행끼리만 비교했다. 기존 순서(rank) 점수가 지난 실측과 달랐다: 1.7B 51(11-13) → 46 (+9 / −14), Mi:dm 55 → 60 (+10 / −5), Qwen3.5-4B 60 → 62 (+9 / −7). 그 사이 코드 변경이나 실행마다의 흔들림으로 보이며, 이번 결론은 같은 날 짝지은 비교에서 나왔다.
  • 골든셋 하나, 모델 셋만 재었다. Kanana·EXAONE·0.6B 등 다른 모델은 재지 않았으므로 기본으로 끈다.
  • 측정은 Python 판으로 했다. Rust 판은 같은 프롬프트를 만들도록 구현한 뒤 글자 단위로 맞는지 확인한다(10장).

5. 설정 — config.yaml

generation: 절에 모델 별칭 목록을 하나 더한다. 저장소의 config.yaml(배포본 원본)에는 Qwen3-1.7B 를 기본으로 적는다.

generation:
  ...
  reverse_context_models: [qwen3-1.7b-q4]
                                # 근거를 거꾸로 넣을 답변 모델 별칭 목록 — [3] 3위 → [2] 2위 → [1] 1위 → [질문]
                                #   1위 근거가 질문 바로 앞에 오고, 번호는 순위 그대로라 인용 번호·화면 출처는 같다.
                                #   골든 100문항(2026-11-18~19, 규칙 지표): Qwen3-1.7B 46 → 54(+9/−1, p=0.02),
                                #   Mi:dm 2.0 Mini 60 → 59(차이 없음), Qwen3.5-4B 62 → 56(+1/−7, 나빠짐) → 모델별로만 켠다.
                                #   빈 목록 [] 이면 모든 모델이 지금처럼 1위부터 넣는다.
                                #   ⚠️ 목록에 모델을 더하려면 골든셋으로 다시 재 보고 넣을 것
  • 키 이름: reverse_context_models (11장 ③)
  • 키가 없을 때: 코드 기본값도 [qwen3-1.7b-q4] 다(11장 ①). 그래서 설치 파일이 config.yaml 을 덮어쓰지 않는 기존 PC 도 업데이트만으로 켜진다. 끄려면 reverse_context_models: [] 를 적는다. 저장소 config.yaml 의 값과 코드 기본값을 늘 같게 둔다.
  • 값: 모델 별칭 목록. generation.model 과 같은 별칭 규칙(소문자 영숫자 · . · -, 64자까지)을 따른다. 받기로 더한 모델(models/<별칭>.model.json)의 별칭도 적을 수 있다.
  • 모델 선택은 건드리지 않는다: generation.model 줄은 그대로다. 설정 > 모델에서 다른 모델로 바꾸면 그 모델이 목록에 없으므로 자동으로 지금 배치로 돌아간다.

6. 동작 규칙

  1. 근거를 받은 생성기가 지금 답하는 모델의 별칭이 목록에 있는지 본다. 비교는 소문자·앞뒤 공백 제거 후 같은지로 한다.
  2. 질문 답변일 때만 뒤집는다 — 생성기에 지시문을 따로 넘기지 않은 호출(system = None, 설정의 답변 지시문을 쓰는 경우)이다. 문서 개요처럼 지시문을 따로 넘긴 호출(Some(OVERVIEW_SYSTEM))은 목록과 상관없이 지금 순서다(11장 ②).
  3. 뒤집을 때는 근거 순서만 바꾼다. 각 근거의 번호는 순위 번호를 그대로 쓴다: [n] n위 … [1] 1위.
  4. 표 펴기(flatten_tables)·근거 줄이기(n_ctx 넘칠 때 가장 긴 근거를 20%씩 깎기)는 지금과 같다. 순서만 다르다.
  5. 목록에 없으면, 또는 [] 이면 지금과 글자 하나까지 같은 프롬프트를 만든다. 키가 없으면 [qwen3-1.7b-q4] 로 본다.
  6. 모델을 정하는 방식은 그대로다: generation.model, 정밀 모드, 명령의 --model 로 한 번 바꾸기 — 어느 경로든 실제로 답하는 모델의 별칭으로 판단한다.

잘못된 값은 다른 설정과 같은 방식으로 다룬다(Python settings.py 스키마 · Rust 판 설정 검사표): 목록이 아니거나 별칭 규칙에 어긋나는 항목이 있으면 설정 오류로 알리고 시작하지 않는다(어느 항목이 틀렸는지 오류문에 밝힌다). 값을 비워 두면(reverse_context_models:) 코드 기본값을 쓴다. 목록에 적힌 별칭이 설치돼 있지 않은 것은 오류가 아니다(그 모델을 고르지 않으면 쓰이지 않을 뿐).

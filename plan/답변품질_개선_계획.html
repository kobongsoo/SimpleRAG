2진단 — 왜 F·AR 이 낮은가

근거가 완벽한 문항도 답이 흔들린다. 병목은 생성 쪽이고, 그다음이 사본·표 같은 근거 구성이다.

  • 0.722F, CR = 1.0 인 82문항
    필요한 내용이 근거에 다 있어도 Faithfulness 가 0.72 에 머문다. 검색을 더 고쳐도 F 의 대부분은 남는다.
  • 0.868 / 0.593F, 핵심어 적중 / 미적중
    틀린 답이 곧 근거 없는 주장이다. 답의 정확도를 올리는 실험이 F 를 올린다.
  • 0.622 / 0.719F, 150자 초과 / 이하
    "3~5문장으로 요약" 지시가 문장을 늘리고, 늘어난 문장이 근거 없는 주장이 된다.
  • 0.637 / 0.683AR, "[1] 문서명 >" 로 시작 / 그 외
    근거 머리를 옮겨 적으며 시작하는 답은 질문에 바로 답하지 않는다.
  • 0.50 / 0.887CR, 사본 중복 7문항 / 나머지
    제목 접두 때문에 사본 제거가 안 걸려 같은 본문이 근거 3칸 중 2칸을 차지한다(§36.6).
  • 5 유형0.6B 실패 사례
    지시문 되뱉기(g004·g034) · 표 열 혼동(g048, 15,000→25,000) · 짧은 사실 바꿔 쓰기(g063) · 없는 조항 번호(g029 "[13조]") · 사본 섞기(g017).

4진행 순서

  1. 0-1

    판정 잡음 폭 재기 완료

    무엇

    왜
    g094 처럼 판정 LLM 이 틀리는 경우가 있다. 잡음보다 작은 차이를 개선으로 읽지 않기 위해.
    결과
    잡음 폭(짝 95%) — F ±0.028 · AR ±0.006 · CR ±0.020. 같은 설정 재수집 답변은 100/100 동일(생성은 결정적) · TTFT 중앙값은 0.2초 흔들림. REPORT §37
  2. 0-2

    실험별 결과 폴더 지원 완료

    왜
    결과 경로가 하나라 실험끼리 덮어썼다. 문항별 짝 비교가 가능해야 한다.
    결과

큰 레버 — 답변 모델 교체

F·AR 에 가장 큰 효과가 기대되지만 속도를 먼저 통과해야 한다. TTFT 관문을 넘지 못하면 품질은 재지 않는다.

  1. 2-1

    qwen3-1.7b-q4 iGPU TTFT 관문 불합격

    무엇
    이미 보유한 1.7B 로 골든셋 20문항 TTFT 만 잰다(SIMPLERAG_GEN_BACKEND=auto).
    왜
    CPU 전용일 때 TTFT 14.7초로 탈락했다(§30). iGPU 에서 LLM 구간이 2.25 → 0.8초가 됐으므로 다시 볼 만하다. 0.6B 는 짧은 사실을 바꿔 쓰는 실수가 더 많았다(§14.5).
    관문
    중앙값 ≤ 3.0초, 3초 이내 ≥ 90%
    결과
    20문항 TTFT p50 3.54초 · 3초 이내 6/20 — 불합격. iGPU prefill 291 t/s(0.6B 766). 전체 응답 p50 10.2초. 대신 핵심어 8→12(사실상 5 얻음/0 잃음). 다음 경로는 D6(REPORT §41)
  2. 2-2

    1.7B 품질 측정 품질 상승 확정 속도 불합격

6측정 방법

한 실험의 절차

  • 변경은 하나만. 설정은 config.yaml 로, 코드는 한 커밋 단위로.
  • 답변 수집 → F·AR 채점(thinking 끔, NaN 재채점) → 검색을 건드렸으면 CR 추가.
  • 506문항 핵심어 정답률을 같은 설정으로 돌려 McNemar 로 짝 비교.
  • CP(thinking 켬, 약 1시간)는 4-1 최종 측정에만.
  • TTFT 는 수집 로그의 중앙값·p90·3초 이내 비율.

판정 설정 (§36 과 동일)

  • 판정 LLM qwen3.6-35b-a3b @ 10.10.19.50:18001, temperature 0
  • 임베딩 qwen3-embedding:8b @ :18002 (AR 전용)
  • ragas 0.4.3 — 수집은 .venv, 채점은 시스템 python
  • 두 채점을 동시에 돌리지 않는다 — 동시 부하에서 NaN 이 늘었다
# 수집 (프로젝트 가상환경) — 실험 ID 폴더에 저장
.venv\Scripts\python bench\ragas_golden.py collect --exp e11_dedup
# F · AR · CR 채점, 빈 칸만 재채점하며 이어하기

# 기준선과 짝 비교 — 잡음 폭(noise_band.json) 기준 상승/하락/잡음 이내 판정
python bench\ragas_compare.py baseline e11_dedup
# 506문항 핵심어 정답률 (같은 실험 폴더에 저장)

7보류한 것

청크 크기 128 → 192 / 256§17 에서 정답률이 평평했다. 0.6B 에는 긴 근거가 방해가 된다2단계에서 모델이 바뀐 뒤

1결론

A. 폴더 아이콘 — 된다. 관리자 권한도 필요 없다.
  • 폴더는 Windows 가 제공하는 SHGetSetFolderCustomSettings 한 번으로 바꾼다. 이 API 가 desktop.ini 쓰기(UTF-16) · desktop.ini 숨김+시스템 속성 · 폴더 읽기전용 속성 · 탐색기 새로고침 알림을 한꺼번에 처리한다. 손으로 desktop.ini 를 쓰면 이 넷 중 하나를 빠뜨려 아이콘이 안 바뀌는 일이 잦다.
  • 볼륨(C:\ · D:\)은 desktop.ini 가 "내 PC"의 드라이브 아이콘에 반영되지 않는다. 대신 사용자 레지스트리 HKCU\Software\Classes\Applications\Explorer.exe\Drives\<문자>\DefaultIcon 에 아이콘 경로를 쓴다 — 관리자 불필요, 이 사용자에게만 보인다.
  • 원래 값은 desktop.ini 안 [MoAI-S] 절과 앱 상태 파일 두 곳에 백업하고, 폴더를 인덱싱에서 빼거나 옵션을 끄면 그대로 되돌린다.
  • 아이콘은 Win11 노란 폴더(드라이브는 회색 드라이브) 오른쪽 아래에 빨간 M 배지. 16px 에서는 배지를 크게 그린 별도 그림을 쓴다(§6).
B. 탐색기 모드 — 된다. 다만 "쪽 번호"를 먼저 바로잡아야 한다.
  • 검색만 하고 답을 만들지 않으므로 빠르고 가볍다 — 실측 top-30 검색 484ms(리랭킹 443ms 포함), 생성 LLM 을 올릴 필요가 없다.
  • 막히는 곳: 인덱스의 청크 쪽 정보(page_from·page_to)는 청크가 아니라 절 전체의 범위다. 실측 4,616 청크 중 한 쪽으로 딱 떨어지는 것은 15.5%, 10쪽 넘게 퍼진 것이 56%, 최대 69쪽. 이대로는 "그 쪽으로 이동"이 안 된다. → 청킹 때 블록마다 가진 쪽 번호로 청크의 실제 시작 쪽을 남기도록 고치고(재인덱싱 1회), 옛 인덱스는 검색 때 PDF 본문 대조로 보정한다(§13).
  • 화면은 Windows 11 탐색기 모양 — 주소줄 · 검색 상자 · 왼쪽 탐색 창 · 가운데 문서 ▸ 쪽 자세히 보기 · 오른쪽 미리 보기 창(그 쪽을 띄우고 청크를 강조) · 아래 상태 표시줄(§10).
  • "그 쪽에서 열기"는 두 갈래: ① 앱 안 미리 보기(WebView2 PDF 뷰어 #page=N) ② 기본 PDF 앱 — 앱을 알아내 앱별 쪽 인자를 붙인다(Edge·Chrome·Whale·Acrobat·SumatraPDF). 모르는 앱이면 파일만 열고 "N쪽" 안내(§14).
  • 모드는 RAGSearchBox.ini [UI] Mode = explorer | rag, 기본 explorer. 설정 창 "화면 모드"에서 바꾸고 다시 시작 없이 바로 적용(§16).

3A-1 폴더 아이콘 — desktop.ini 원리

탐색기는 폴더를 그릴 때 그 폴더 안의 desktop.ini 를 읽는다. 단, 폴더에 읽기전용(또는 시스템) 속성이 있을 때만 읽는다 — 모든 폴더의 desktop.ini 를 열어 보면 느려지므로 속성을 "읽어 볼 만한 폴더" 표시로 쓰는 것이다. 이 조건 때문에 desktop.ini 만 써 두고 아이콘이 안 바뀌는 일이 가장 흔하다.

바꾼 뒤 desktop.ini 모양

[.ShellClassInfo]
IconResource=C:\Users\<사용자>\AppData\Local\RAGSearchBox\icons\moai-folder.ico,0
InfoTip=MoAI-S 인덱싱 폴더 — 자연어로 문서와 쪽을 찾을 수 있습니다

[MoAI-S]
Managed=1
Created=0                 ; 1 이면 desktop.ini 를 우리가 새로 만든 것 → 되돌릴 때 파일째 지운다
Orig.IconResource=        ; 원래 값(비었으면 원래 없던 키)
Orig.InfoTip=
IconVersion=1
조건내용누가 처리
desktop.ini 인코딩한글 경로 · InfoTip 이 있으므로 UTF-16 LE (BOM). ANSI 로 쓰면 cp949 아닌 환경에서 깨진다API
desktop.ini 속성숨김 + 시스템 (사용자 눈에 안 띄게, 탐색기가 시스템 파일로 취급)API
폴더 속성읽기전용(기본) — PathMakeSystemFolder 와 같은 규칙. 폴더 읽기전용은 "안의 파일 쓰기 금지"가 아니라 표식일 뿐이라 인덱싱·감시에 영향 없음API
탐색기 새로고침SHChangeNotify(SHCNE_UPDATEDIR, SHCNF_PATHW, 폴더) — 열린 탐색기 창에 바로 반영API(+ 보강 호출)
[MoAI-S] 절우리 표식 · 원래 값 백업. 앱 상태 파일이 사라져도 desktop.ini 만 보고 되돌릴 수 있다직접(WritePrivateProfileStringW)

쓰는 API

SHFOLDERCUSTOMSETTINGS fcs = { cbSize, dwMask = FCSM_ICONFILE | FCSM_INFOTIP,
                               pszIconFile = ico 경로, iIconIndex = 0, pszInfoTip = 안내글 };
SHGetSetFolderCustomSettings(&fcs, 폴더, FCS_FORCEWRITE);   // 적용
SHGetSetFolderCustomSettings(&fcs, 폴더, FCS_READ);         // 적용 전 원래 값 읽기(백업)

Rust 에서는 이미 쓰는 windows 크레이트의 Win32_UI_Shell 기능에 들어 있다(새 의존성 없음). Python 판은 ctypes 로 같은 함수를 부른다.

아이콘 파일은 폴더 안에 넣지 않고 %LOCALAPPDATA%\RAGSearchBox\icons\ 에 둔다. 폴더 안에 넣으면 사용자 문서 폴더에 우리 파일이 늘고, 폴더 감시(watcher)가 변경으로 잡는다. exe 안 리소스(RAGSearchBox.exe,-2)를 가리키는 방법도 있지만 exe 를 옮기거나 업데이트하면 깨지므로, exe 에 그림을 넣어 두고(include_bytes!) 처음 쓸 때 위 폴더로 꺼내 쓴다.

4A-2 적용 · 되돌리기 흐름

적용 (인덱싱 폴더 추가 · 시작할 때 맞춰 보기)

  1. 경로가 드라이브 루트(PathIsRootW)면 §5 볼륨 방식으로, 아니면 아래
  2. 아이콘 파일이 없거나 버전이 낮으면 exe 에서 꺼내 씀
  3. desktop.ini 가 있으면 FCS_READ 로 원래 IconResource · InfoTip 을 읽어 둠. 이미 [MoAI-S] Managed=1 이면 경로만 최신으로 갱신하고 끝
  4. FCS_FORCEWRITE 로 적용 → [MoAI-S] 절에 백업 기록
  5. 앱 상태 %LOCALAPPDATA%\RAGSearchBox\folder_icons.json 에 {경로, 종류, 원래 값} 추가
  6. 실패(권한 · 네트워크 · 읽기 전용 매체)는 로그 한 줄 + 설정 창 폴더 메모 "아이콘을 바꾸지 못함(권한)" — 인덱싱은 그대로 진행

되돌리기 (폴더 빼기 · 옵션 끄기 · 트레이 "아이콘 원래대로")

  1. desktop.ini 의 [MoAI-S] 절을 읽는다(없으면 상태 파일 값)
  2. Created=1 → desktop.ini 삭제 + 폴더 읽기전용 해제(PathUnmakeSystemFolder)
  3. Created=0 → Orig.* 값으로 되쓰고 [MoAI-S] 절만 지움(다른 키 — LocalizedResourceName 등 — 은 손대지 않음)
  4. 단, 그 사이 사용자가 아이콘을 직접 바꿨으면(IconResource 가 우리 경로가 아님) 건드리지 않는다
  5. SHChangeNotify 로 새로고침, 상태 파일에서 제거
설정 창 "추가…"→scope 목록 저장→folder_icon::apply→자동 인덱싱 시작
설정 창 "빼기"→scope 목록 저장→folder_icon::restore→인덱스에서 그 폴더 문서 정리
  • 하위 폴더에는 붙이지 않는다 — 지정한 뿌리 폴더 하나만. 하위마다 desktop.ini 를 만들면 사용자 폴더를 어지럽히고, 범위는 뿌리만 보여도 충분하다.
  • 시작할 때 맞춰 보기 — ini 를 손으로 고친 경우를 위해, 시작 시 scope 목록과 상태 파일을 비교해 빠진 것은 적용, 남은 것은 되돌린다.
  • 폴더 감시는 TEXT_EXTS 확장자만 보므로 desktop.ini 변경은 인덱싱을 일으키지 않는다(watcher.rs 확인).

5A-3 볼륨(C:\ · D:\) 아이콘

"내 PC"에 보이는 드라이브 아이콘은 폴더 아이콘과 다른 경로로 정해진다. 드라이브 루트에 desktop.ini 를 두면 그 드라이브를 열었을 때의 폴더 보기에만 영향이 있고 "내 PC"의 드라이브 그림은 그대로다. 가능한 방법은 넷이다.

방법위치권한보이는 범위판단
① 사용자 레지스트리HKCU\Software\Classes\Applications\Explorer.exe\Drives\D\DefaultIcon
(기본값) = …\moai-drive.ico,0		불필요이 사용자채택
② 컴퓨터 레지스트리HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer\DriveIcons\D\DefaultIcon관리자모든 사용자선택 사항 — 관리자 설치판에서만
③ 루트 autorun.infD:\autorun.inf 의 [autorun] icon=C:\ 루트는 관리자모든 사용자기각 — 백신이 autorun.inf 를 막거나 지움, 루트에 파일을 남김
④ 루트 desktop.iniD:\desktop.iniC:\ 는 관리자—기각 — 드라이브 아이콘에 반영 안 됨
  • 적용: 키가 이미 있으면 원래 기본값을 상태 파일에 백업 → 우리 경로로 씀 → SHChangeNotify(SHCNE_ASSOCCHANGED, SHCNF_IDLIST, 0, 0) 와 SHCNE_UPDATEITEM("D:\") 로 새로고침.
  • 되돌리기: 우리가 만든 키면 DefaultIcon 키째 삭제(빈 Drives\D 도 정리), 원래 값이 있었으면 되씀.
  • 드라이브 문자 기준이라 USB 를 다른 문자로 꽂으면 아이콘이 따라가지 않는다. 고정 디스크(C:\ · D:\)는 문제없다. 네트워크 드라이브(Z:)에서도 같은 키가 듣는지는 P0 확인(§17).
  • 폴더 아이콘과 달리 그 드라이브를 연 뒤 보이는 폴더 아이콘은 바뀌지 않는다 — 드라이브 자체가 "인덱싱 폴더"이므로 "내 PC" 에서 보이는 것으로 충분.
  • 참고: 드라이브 전체(C:\)를 인덱싱 폴더로 잡는 것은 아이콘과 별개로 인덱싱 시간 · 용량 부담이 크다. 설정 창에서 루트를 고르면 "드라이브 전체를 인덱싱합니다(문서 N개 예상)" 확인을 한 번 띄우는 것을 권한다.

검색어→dense + BM25 (후보 60)→RRF→사본 거르기→리랭킹 상위 40→문서별 묶기→쪽별 합치기→발췌 · 강조

13B-6 쪽 번호 바로잡기

탐색기 모드의 핵심 약속은 "그 쪽으로 간다"인데, §9 처럼 지금 청크의 쪽 범위는 절 전체다. 원인과 고칠 자리는 분명하다.

지금

  1. PDF 추출(docmodel/pdf.rs) — 블록마다 정확한 쪽(Block.page)이 있다
  2. 절 만들기(assemble.rs) — 절의 page_from/to = 블록 쪽의 최소/최대
  3. 청킹(chunk.rs split_blocks → pack_units) — 절 본문을 문자열로 이어 붙인 뒤 예산대로 자른다. 이때 블록↔쪽 연결이 끊긴다
  4. chunk_meta — 쪽은 "청크가 속한 절들의 합" → 긴 절의 청크는 모두 넓은 범위

고친 뒤 (인덱싱 때)

  1. 절마다 블록 지문표를 만든다: 블록 본문 앞 24자(공백 제거) → 쪽
  2. 청크가 만들어지면 청크 본문(접두 뗀 것)을 같은 방식으로 훑어 처음 만나는 블록의 쪽 = page, 마지막 블록의 쪽 = page_to
  3. 표 조각처럼 머리글을 다시 붙인 청크는 머리글 다음 첫 행으로 잡는다
  4. payload 에 page(시작 쪽) 추가, page_from/to 는 청크 자체 범위로 좁힌다. 못 찾으면 지금 값 유지 + page_exact=false
  • 재인덱싱 필요 — 지금 30문서 기준 수 분. 인덱스에 page 가 없는 옛 청크는 아래 보정으로 동작하게 해 재인덱싱 전에도 기능은 쓸 수 있게 한다.
  • 옛 인덱스 보정(검색 때): 쪽 범위가 2쪽 이상인 결과만, 이미 들어 있는 pdfium(pdfium.rs read_pages)으로 그 범위의 쪽 글을 읽어 청크 앞 40자가 나오는 쪽을 찾는다. 문서마다 쪽 글을 메모리에 캐시(LRU 5문서). 큰 해설서(282쪽)도 범위 안 쪽만 읽으므로 수십 ms 로 예상 — §17 에서 잰다.
  • PDF 아닌 형식: pptx · xlsx 는 이미 블록 쪽이 슬라이드 · 시트 번호로 들어 있다(같은 고침이 그대로 듣는다). docx · hwp · hwpx 는 "쪽을 뽑을 수 없다"가 아니라 지금 추출기가 뽑지 않는다 — docx 추출기(docx.rs para_runs)는 쪽 나누기 <w:br type="page"> 를 일부러 건너뛰고, hwpx 추출기에는 쪽 처리가 없으며, hwp 는 블록 없는 legacy(평문) 경로다. 이 형식들은 쪽이 파일에 고정되지 않고 프로그램이 열 때 배치로 정해지므로, 파일에 남은 배치 단서로 근사 쪽을 붙이는 것을 2단계에서 검토 · 시험한다(§14-④). 1차에서는 "쪽" 열이 비고 열기는 파일만 연다.
  • Python 판 chunk.py _chunk_meta 도 같은 구조라 같은 고침을 넣는다(두 판 같은 인덱스 규칙).

14B-7 그 쪽에서 열기

지금 앱은 파일을 ShellExecuteW("open", 경로)(win.rs open_path)로만 연다 — 이 방식으로는 쪽을 넘길 수 없다. 두 갈래를 둔다.

① 앱 안 미리 보기 창 (클릭 · Space)

  • 미리 보기 영역에 두 번째 WebView2를 두고 file:///D:/…/문서.pdf#page=5 로 이동한다. WebView2 에는 Edge 의 PDF 뷰어가 들어 있어 별도 프로그램이 없어도 되고, 쪽 이동이 표준 URL 조각으로 된다.
  • 목록 화면 WebView 안의 <iframe> 으로는 file:// 이 막힐 수 있어 별도 WebView(같은 창의 자식)로 둔다 — P0 확인.
  • 2단계 — 청크 강조: Edge PDF 뷰어는 글 강조를 URL 로 받지 못한다. 강조가 필요하면 pdfium 으로 그 쪽을 그림으로 그리고(FPDF_RenderPageBitmap) 청크 글자 위치(FPDFText_Find… · GetCharBox)에 노란 상자를 덧그린다 — 초안의 노란 박스가 이것.
  • 이 미리 보기는 PDF 전용이다. WebView2(Edge 엔진)는 PDF · 이미지 · txt · html 만 직접 그리고, docx · hwp · hwpx · pptx · xlsx 는 못 그린다 — 다른 형식은 §14-③.

LM Studio 의 "탐색" 화면처럼, 설정 창에서 답변 모델 목록을 보고 받기 → 설치 → 사용까지 한 번에 하게 한다. 모델은 기본(3B 이하)과 정밀(3B 이상)으로 나누고, 받기 전에 이 PC 의 메모리·그래픽·CPU 를 보고 맞는 모델을 먼저 보여 준다. 모델은 GitHub 릴리스에 올린 모델별 설치 파일(.exe)로 받는다. 이것으로 지금의 "정밀 모드" 스위치와 정밀 모델 추가 설치 파일을 없앤다.

1. 요구 사항 정리

  • 설정 창에서 모델을 받고, 바로 골라 쓰게 한다. 다른 프로그램을 따로 실행하거나 파일을 옮기지 않는다.
  • 모델은 기본 = 3B 이하, 정밀 = 3B 이상으로 나눠 보인다.
  • 추천은 받기 전에 한다. 후보 모델을 미리 받아 재 보는 방식은 쓰지 않는다. 이 PC 의 사양으로 판단한다.
  • 모델은 GitHub 릴리스의 설치 파일(.exe)로 배포한다. 앱은 그 파일을 받아 실행해서 설치한다.
  • 후보: 기본 — Kanana Nano 2.1B · LFM2.5-1.2B-Instruct · Qwen3.5-2B · Mi:dm 2.0 Mini / 정밀 — Qwen3.5-4B.
  • "Qwen3-4B 정밀 모델 설치 파일을 받아 쓰라"는 지금 안내와 정밀 모드 스위치는 없앤다.
  • 모델 품질 측정은 이 화면 설계가 끝난 뒤에 한다. 그래서 이 설계서의 품질·속도 숫자 중 일부는 측정 전으로 남긴다.

4. 받기 전 추천 — PC 사양으로

후보 모델은 받지 않는다. 대신 ① 이 PC 사양과 ② 이미 내장된 1.7B 로 처음 실행할 때 잰 속도를 쓴다. ②는 설치할 때 이미 있는 모델로 잰 값이라 따로 받을 것이 없다. ②가 아직 없으면(처음 실행 직후 등) ①만으로 판단한다.

4-1. 읽는 사양 (모두 Windows 기본 기능, 1초 안에 끝남)

항목읽는 방법쓰는 곳

4-2. 판정 세 단계

  1. 돌릴 수 있나 — 필요 메모리 = 모델 파일 크기 + 0.6GB(대화 기억 공간) + 1.5GB(앱 · 임베딩 · 리랭커 · 화면). 전체 메모리가 이보다 적으면 이 PC 메모리로는 어려움. 받기 단추는 남기되, 누르면 한 번 더 묻는다.
  2. 얼마나 빠른가 — 예상 첫 글자 = 내장 1.7B 첫 글자 × 그 모델의 첫 글자 비. 1.7B 첫 글자는 600 토큰 ÷ prefill_tps 로 어림한다(구현 때 맞춘 값 — 이 PC 의 iGPU 260 토큰/초에서 실제 첫 글자 중앙값 2.3초가 나오는 토큰 수). ②도 없으면 사양 등급으로 대신한다: 외장 GPU 4GB 이상 · Vulkan iGPU · CPU 8스레드 이상 · 그 밖.
    표시 등급: 4초 이하 빠름 · 4~10초 보통 · 10초 넘음 느림.
  3. 추천 — 기본·정밀 묶음마다 돌릴 수 있고, 예상 첫 글자가 한도 안인 모델 가운데 품질 순위가 가장 높은 것 하나에 추천을 단다. 한도: 기본 4초, 정밀 10초. 품질 순위는 목록 파일의 rank(측정 결과로 정한 값)를 쓴다. 측정 전 모델에는 추천을 달지 않는다. 정밀 묶음에 한도 안 모델이 없으면 "이 PC 에서는 정밀 모델이 느립니다(약 N초)"라고 적고 추천을 달지 않는다.

5-1. 줄 정렬과 배지

  • 묶음마다 추천 → 사용 중 → 설치됨 → 받지 않음 순서로 놓고, 같은 순서 안에서는 품질 순위 순으로 놓는다. 내장 모델은 사용 중이 아니면 설치됨과 같이 친다.
  • 배지: 추천 · 사용 중 · 한국어 · 느림 · 메모리 부족 · 이전 정밀. 한 줄에 두 개까지만 보인다.
  • 예상 첫 글자는 "약 N초 · 빠름/보통/느림"으로 적는다. ②(실제 속도)가 없으면 등급만 적고 "(사양으로 어림)"을 붙인다.
  • 줄 맨 앞에 모델 아이콘(30px)을 둔다(§5-4). 줄의 상세 단추나 모델 이름을 누르면 상세 화면(§5-3)으로 넘어간다. 처음 설계의 "줄 펼치기"는 상세 화면으로 바꾼다.

5-3. 상세 화면

LM Studio 의 오른쪽 상세 칸과 같은 역할이다. 설정 창은 폭이 좁아 칸을 둘로 나누지 않고, 모델 탭 판 전체를 상세 화면으로 바꾼다. 맨 위 ← 모델 목록을 누르거나 Esc 를 누르면 목록으로 돌아가며, 보던 스크롤 위치를 지킨다. 받는 중이면 상세 화면에서도 진행 막대가 같이 움직인다.

6. 받기·설치·사용 흐름

받기 누름→디스크·메모리 확인→조각 받기 (.exe · .bin)→SHA256 확인→설치 파일 조용히 실행→모델 파일 확인→설치 파일 지우기→설치됨→사용 누름→config.yaml 바꾸고 다시 올리기

6-1. 받기 (WinHTTP)

  • Windows 내장 WinHTTP 로 받는다. 회사 프록시(인터넷 옵션 · 자동 구성 스크립트)를 그대로 따르고, GitHub 릴리스 주소가 다른 곳으로 넘겨 주는 것도 자동으로 따라간다. windows crate 기능 Win32_Networking_WinHttp 만 더하면 되고 새 라이브러리는 들이지 않는다.
  • 받는 곳: %LOCALAPPDATA%\MoAISearch\downloads\<별칭>\. 받는 동안 파일 이름은 .part 이고, 다 받으면 원래 이름으로 바꾼다.
  • 이어 받기: .part 크기부터 Range 요청을 보낸다. 앱을 껐다 켜도 이어 받는다.
  • 진행률은 설정 창이 1초마다 새로 읽는다(받은 크기, 속도, 남은 시간 — 기존 설정 창 갱신 주기를 그대로 쓴다).
  • 끊기면 5초, 15초, 45초 뒤 세 번 다시 시도하고, 그래도 안 되면 "멈춤"으로 둔다.

6-2. 확인과 설치

  • 조각마다 SHA256 을 목록 파일의 값과 비교한다. 다르면 그 조각을 지우고 "받은 파일이 손상되었습니다 — 다시 받기"로 표시한다. 내려받은 실행 파일을 그냥 실행하지 않게 하는 안전장치다(아직 코드 서명 전이라 해시가 유일한 확인 수단).
  • 설치 파일을 /VERYSILENT /SUPPRESSMSGBOXES /NORESTART 로 실행하고 끝날 때까지 기다린다. 사용자 권한으로 설치하므로(PrivilegesRequired=lowest) 관리자 확인 창은 뜨지 않는다. 앱이 직접 받은 파일에는 "인터넷에서 받은 파일" 표시가 붙지 않아 SmartScreen 경고도 뜨지 않는다.
  • 종료 코드가 0 이고 models\<파일> 크기가 목록 파일 값과 같으면 설치됨이다. 그런 뒤 설치 파일과 조각을 지운다(2.7GB 를 아끼기 위해서다).

6-3. 사용과 삭제

  • 사용: config.yaml 의 generation.model 줄 값만 바꾼다. 주석은 지키며, 지금 precision.rs 가 쓰는 방식 그대로다. 그다음 워커를 다시 올린다(정밀 모드 스위치 때와 같은 경로). 다시 올리는 동안 기본 탭과 같은 진행 막대를 보인다.
  • 새 모델을 처음 올릴 때 생성 백엔드 측정(gen_backend.json)을 그 모델로 다시 한다(지금 동작 그대로). 그 결과로 "이 PC 예상 첫 글자"를 실제 값으로 고쳐 보인다.
  • 삭제: 사용 중이 아닌 설치 모델만 지울 수 있다. 파일을 지우고, 모델 옆 설명 파일(§7-3)과 라이선스 파일도 함께 지운다.

7. 배포 — 모델별 설치 파일과 목록 파일

7-1. 릴리스 구성

  • kobongsoo/MoAI-S 에 앱 버전과 따로 노는 모델 전용 릴리스 models-1 을 하나 둔다. 지금처럼 정밀 모델을 앱 버전마다 다시 올리면(2.5GB) 시간과 저장 공간이 낭비되기 때문이다. 모델이 바뀔 때만 파일을 더하거나 바꾼다.
  • 파일 이름: MoAISearch_Model_<별칭>_r<판>.exe. 1.9GB 를 넘으면 지금처럼 -1.bin, -2.bin 조각을 함께 둔다(정밀 4B 만 해당).
  • 사용자가 직접 받을 때를 위해 릴리스 설명에 모델 표와 "받은 .exe 와 .bin 을 같은 폴더에 두고 .exe 를 실행" 안내를 적는다.

7-2. 설치 파일 틀 — installer_model.iss

installer_precision.iss 를 일반화한다. 빌드 스크립트가 모델마다 /DAlias= /DModelFile= /DModelName= /DAppIdGuid= /DRev= 를 넘긴다.

  • AppMutex 를 뺀다. 앱이 켜진 채로 앱이 설치 파일을 실행하기 때문이다. 새 모델 파일은 아직 아무도 쓰지 않으니 겹치지 않는다. 사용 중인 모델을 다시 설치할 때는 앱이 먼저 워커를 내린다.
  • 설치 폴더는 지금처럼 기본 프로그램의 제거 정보 레지스트리에서 찾는다. 기본 프로그램이 없으면 멈춘다(사용자가 직접 실행한 경우).
  • 넣는 파일: models\<모델>.gguf + models\<별칭>.model.json(§7-3) + licenses\models\<별칭>.txt.
  • Uninstallable=no 는 유지한다. 지우기는 앱의 삭제 단추나 기본 프로그램 제거로 한다.

7-3. 모델 옆 설명 파일 — <별칭>.model.json

워커(simplerag-rs)는 모델 표를 코드에서 읽는다. 표에 없는 별칭이면 이 파일을 읽어 파일 이름·대화 형식·이웃 청크 여부를 정한다. 그래서 이미 있는 대화 형식을 쓰는 모델은 앱을 다시 배포하지 않고 추가할 수 있다.

{ "alias": "qwen3.5-4b-q4", "file": "Qwen3.5-4B-Q4_K_M.gguf", "format": "qwen3",
  "tier": "precise", "neighbors": false, "min_app": "0.1.4" }

8. 정밀 모드 없애기와 옮겨 가기

  • config.yaml: generation.model 이 답변 모델을 정하는 유일한 값이 된다. 이웃 청크는 모델 설명(neighbors)을 따르고, 새 키 generation.neighbors: auto(auto/on/off)로 직접 바꿀 수도 있다.
  • generation.precision 은 읽기만 한다. 0.1.3 에서 올라온 사용자 가운데 precision: true 이고 Qwen3-4B 파일이 있으면, 처음 실행할 때 model: qwen3-4b-q4 로 바꾸고 precision: false 로 적는다. 그 결과 Qwen3-4B 를 이웃 청크와 함께 쓰게 되어, 바꾸기 전과 똑같이 답한다.
  • Qwen3-4B 는 목록에 retired 로 남는다. 설치한 사람에게만 "이전 정밀"로 보이고 사용·삭제는 그대로 된다.
  • SIMPLERAG_PRECISION 환경변수와 명령줄 --model 은 그대로 둔다(측정 스크립트가 쓴다). 환경변수는 "모델 qwen3-4b-q4 + 이웃 켬"과 같은 뜻으로 남긴다.
  • 기본 탭의 정밀 모드 상자, precision::WARN 과 안내 글, build_installer.ps1 의 정밀 설치 파일 단계, installer_precision.iss 를 없앤다.
  • 사이트·설명서·릴리스 설명의 "정밀 모드 모델 설치 파일" 안내를 "설정 > 모델" 안내로 바꾸고, 변경 기록에 적는다.

11. 확인 방법과 남은 측정

11-1. 화면·기능 확인

  • 추천 계산: 사양을 바꿔 넣는 단위 시험(16GB/Vulkan · 8GB/CPU · 32GB/외장 8GB · 측정값 없음).
  • 받기: 받다가 네트워크 끊기 → 이어 받기, 앱을 껐다 켜기 → 이어 받기, 조각 하나 일부러 망가뜨리기 → 해시 오류.
  • 설치: 앱이 켜진 채 조용히 설치되는지, 관리자 확인 창·SmartScreen 이 안 뜨는지, 끝난 뒤 설치 파일이 지워지는지.
  • 사용: 모델 바꾸기 → 다시 올리기 → 답 아래 모델 이름 확인. 올리기 실패 시 이전 모델로 되돌리는지.
  • 옮겨 가기: 0.1.3 + 정밀 모드 켬 + Qwen3-4B 설치 상태에서 새 버전으로 올렸을 때 같은 답 조건(4B + 이웃)인지.
  • 회사망 흉내: 프록시를 끊은 상태에서 안내 글과 "배포 페이지 열기", 직접 받은 .exe 설치 뒤 목록에 바로 나타나는지.

11-2. 화면을 만든 뒤 할 측정 (요청대로 나중에)

  1. Kanana Nano 2.1B 라이선스 확인 — 비상업이면 여기서 뺀다.
  2. LFM2.5-1.2B 가 지금 llama.dll(0.3.35)과 Vulkan 에서 열리는지, 대화 형식은 무엇인지.
  3. 둘 다 골든 100문항(규칙 지표) — 10-29 와 같은 조건으로 핵심어 정답·첫 글자를 재서 rank · ttft_ratio 를 정한다.
  4. Qwen3.5-4B 이웃 청크 끔을 다시 확인하고, 모든 모델의 ttft_ratio 를 같은 날 같은 조건으로 다시 잰다.
  5. 사양이 낮은 PC(8GB · CPU 만) 한 대에서 예상 첫 글자와 실제 값의 차이를 재고, 한도(4초 · 10초)와 필요 메모리 공식을 고친다.

12. 정해 주실 것

2026-11-13 결정: 아래 ①~⑧ 모두 제안대로 한다.
① Qwen3-4B 를 새로 받기 목록에서 뺄까요? 제안: 뺀다(retired). 이미 설치한 사람은 "이전 정밀"로 계속 쓰고 지울 수 있다. 정밀 모델은 Qwen3.5-4B 하나만 내놓는다.
② Qwen3.5-4B 는 이웃 청크 없이 쓸까요? 제안: 그렇게 한다(10-29 측정: 이웃을 붙이면 59 → 55). 이것은 11-2 ④에서 다시 확인한다.
③ Qwen3.5-2B 를 목록에 둘까요? 제안: 두되 추천은 하지 않는다. 내장 1.7B 보다 정답이 적고(44 대 50) 느리다. 목록을 짧게 하려면 빼도 된다.
④ 모델 전용 릴리스(models-1)를 앱 버전과 따로 둘까요? 제안: 따로 둔다. 앱을 올릴 때마다 2.7GB 를 다시 올리지 않아도 된다.
⑤ 받은 뒤 저절로 그 모델로 바꿀까요? 제안: 바꾸지 않는다. 정밀 모델은 느려지므로 사용자가 "사용"을 직접 누르게 한다. 트레이 알림으로만 알린다.
⑥ 처음 실행 뒤, 사양이 좋은 PC 에 "정밀 모델을 쓸 수 있습니다" 안내를 한 번 띄울까요? 제안: 이번에는 넣지 않는다. 모델 탭 추천만으로 시작하고, 사용 기록을 본 뒤 정한다.
⑦ 모델 아이콘은 글자 아이콘으로 시작할까요, 공식 로고를 넣을까요? 제안: 글자 아이콘(개발사 색 + 1~2글자)으로 시작한다. 공식 로고는 Qwen · KT · 카카오 · Liquid AI 의 상표 사용 지침을 확인한 뒤 목록 파일의 icon 만 채워 바꾼다. 앱은 다시 배포하지 않는다.
⑧ 상세 화면의 소개 글은 누가 쓸까요? 제안: 모델 카드를 바탕으로 쉬운 한국어 2~4문장으로 직접 쓴다. 시험 결과와 좋은 점·아쉬운 점은 측정 보고서에서 옮긴다. 원문 복사는 하지 않는다.

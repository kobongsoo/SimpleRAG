## 0. 요약

| # | 문제 | 원인 | 고치는 방향 |
|---|------|------|------------|
| 1 | 파일 이름만 바꿔도 **삭제 + 새 문서**로 처리된다 | 이동 판정(`find_moves` · `moved_from` · `copied_from`)이 **내용 해시 + 같은 파일 이름**을 요구 | 이름 조건을 풀어 **내용 해시가 같고 옛 경로가 없으면 이동**으로 본다 |
| 2 | 여러 파일 이름을 한꺼번에 바꾸면(예: 날짜 붙이기 300건) 삭제 안전장치 · 새 문서 허락 대기에 걸린다 | 1 때문에 "300건 사라짐 + 300건 새로 생김" 으로 보인다 | 1 로 함께 풀린다 — 이동은 삭제 · 새 문서로 세지 않는다(지금 코드 그대로) |

## 1. 실측 근거 (2026-11-10)

- 분류함 119건(대상 20건 · 나머지 99건)을 임시 폴더에 복사, 질문 40개(이름형 20 · 내용형 20), 채팅 검색(리랭킹 포함) 문서 순위.
- B = 옛 이름으로 인덱싱한 뒤 `move_doc` 으로 경로 · 이름만 바꿈(벡터 그대로), A = 새 이름으로 다시 인덱싱.

| 이름 바뀜 방향 | 방안 | 이름형 @1 | 이름형 MRR | 내용형 MRR |
|---|---|---|---|---|
| 문서_NN → 뜻 있는 이름 | A 다시 임베딩 | **19/20** | **0.950** | 0.950 |
| | B 옛 벡터 | 14/20 | 0.772 (놓침 1) | 0.942 |
| 뜻 있는 이름 → 문서_NN | A 다시 임베딩 | 14/20 | 0.772 | 0.942 |
| | B 옛 벡터 | 19/20 | 0.950 | 0.950 |

- **B 결과 = 옛 이름 인덱스 결과와 완전히 같음** — 채팅 검색은 payload · `meta.sqlite` 의 파일 이름을 쓰지 않는다. 새 이름을 반영하려면 청크를 다시 만들어야 한다.
- 다시 임베딩 비용: e5-small 약 43~55 청크/s, 문서 평균 ~18청크 → **1건 약 0.3초**. 큰 문서(300청크)는 6초 안팎.
- 한계: 20건 · 질문 40개 1회. 이름형 질문은 새 이름 낱말로 써서 이름 효과가 크게 나오는 쪽.

## 2. 지금 구조 (조사 결과)

### 2-1. 자동 인덱싱 흐름 (앱 → 워커)

```
watcher(ReadDirectoryChangesW) → 5초 조용 → jobs.rs
  /index-plan {root}           → commands::plan → indexer::plan_changes
       todo    = 지문(sha1 경로|mtime|크기)이 다른 파일
       missing = 상태에 있는데 폴더에 없는 문서
       find_moves(missing, files) → (moved, dup)        ← 내용 해시 + 같은 이름
       removed = missing − moved − dup  → delete_guard
     응답 {add, modify, move, remove, delete_blocked}
  jobs.rs on_plan
       add 가 AskAbove 를 넘으면 허락 대기 (move 는 add 로 안 셈)
       remove-doc 들 → index-doc(move · modify · add) 들 → /bm25
  /index-doc {path} → sync_doc_with
       prev 없음 → moved_from(path, chash) → move_doc   ← 내용 해시 + 같은 이름 + 옛 경로 없음
                 → copied_from(path, chash) → copy_doc   ← 내용 해시 + 같은 이름 + 원본 있음
                 → 아니면 새로 파싱 · 청킹 · 임베딩
```

- CLI `index --dir` (`index_folder`) 도 같은 `plan_changes` → `sync_doc_with` 길을 쓴다.
- 즉 **이동 판정은 세 함수에만** 있다: `find_moves`(indexer.rs:979) · `moved_from`(:1017) · `copied_from`(:1026).

### 2-2. 이동 처리 (`move_doc`, indexer.rs:1091)

- 상태 파일 키를 새 경로로 옮기고 `fingerprint · name · folder · mtime` 을 고친다.
- 벡터 저장소 payload 의 `doc_path · doc_name · folder · mtime · gen` 을 고친다(`set_payload_ids`).
- `meta.sqlite` 를 옮긴다(`meta::hook::moved`).
- **청크 글 · 벡터 · BM25 는 그대로** — 청크 글 안의 접두 `[옛제목 > 절]` 도 그대로 남는다.

### 2-3. 청크 접두의 제목

- `parse_doc(path, name, tok)` → `split_structured(text, tok, Some(splitext(name).0), …)` — 제목 = 확장자 뺀 파일 이름.
- 접두 길이가 예산에 들어가므로 제목이 바뀌면 **청크 경계도 조금 바뀔 수 있다**(실측: 같은 119건이 이름에 따라 2,181 · 2,150청크).
  → 접두만 글자 바꾸기로 고치면 새로 인덱싱한 것과 결과가 달라진다. **다시 청킹**한다.

### 2-4. 앱 워커의 벡터 미룸

- 앱 워커는 `index.vectors_background`(기본 켬)라 `index-doc` 이 벡터를 **모두 비워 두고**(`worker_defer_over() = Some(0)`), 쉴 때 `fill_pending` 이 채운다.
- 그대로 두면 이름 바꿈 후 다시 청킹한 문서는 벡터가 빈 채로 기다린다 → **그동안 그 문서가 dense 검색에서 빠진다**(지금 B 보다 나빠짐). §3-3 에서 막는다.

## 3. 설계

### 3-1. 이름 바꿈 판정 — 이름 조건 풀기

세 함수에서 "같은 파일 이름" 을 **필수 조건이 아니라 우선순위**로 바꾼다.

| 함수 | 지금 | 바꾼 뒤 |
|---|---|---|
| `find_moves(missing, files)` | `(내용 해시, 이름)` 이 같은 짝 | `내용 해시` 가 같은 짝. 한 해시에 후보가 여럿이면 ① 같은 이름 ② 같은 폴더 ③ 나머지 순으로 짝짓기 |
| `moved_from(path, chash)` | 해시 · 이름 같고 옛 경로 없음 | 해시 같고 옛 경로 없음. 여럿이면 같은 이름 → 같은 폴더 우선 |
| `copied_from(path, chash)` | 해시 · 이름 같고 원본 있음 | 해시 같고 원본 있음(이름 달라도 복사본 — 벡터를 베낀 뒤 §3-2 제목 갱신) |

- 내용 해시는 파일 전체 sha1 이라 우연히 같을 일은 없다. 같다면 정말 같은 파일이다.
- **비용**: 지금 `find_moves` 는 이름이 같은 새 파일만 내용 해시를 구한다. 이름 조건을 풀면 **새로 생긴 파일 모두**의 해시를 구해야 한다.
  - 사라진 문서가 0건이면 지금처럼 아무것도 하지 않는다(대부분의 대조).
  - 사라진 문서가 있을 때만, 새 파일(= 상태에 없는 경로) 해시를 구한다. 이 파일들은 어차피 곧 `index-doc` 에서 해시를 구하므로 추가 비용은 "한 번 더 읽기" 수준.
  - 큰 파일이 많은 폴더 대비: 해시 전에 **크기**로 걸러 낸다(사라진 문서의 크기 집합에 없는 크기면 건너뜀). 크기는 상태에 따로 없으므로 `docs[*]` 에 `size` 필드를 새로 남긴다(없는 옛 항목은 거르지 않고 해시).

### 3-2. 이동 뒤 제목 갱신 — 상태에 "청킹에 쓴 제목" 남기기

- 문서 항목에 **`chunk_title`** 필드를 새로 둔다 = 청크 접두에 실제로 쓴 제목(확장자 뺀 파일 이름).
  - 새로 인덱싱 · 수정 인덱싱할 때 기록.
  - `move_doc` · `copy_doc` 은 **원본의 `chunk_title` 을 그대로** 둔다(청크 글이 그대로이므로).
  - 옛 항목(필드 없음, Python 판 · 가져오기 포함)은 `name` 의 확장자 뺀 값으로 본다 → 지금 인덱스는 다시 만들 필요 없음.
- `sync_doc_with` 의 "내용이 같음" 분기(지금 `same` 로 끝냄)에서
  `chunk_title != 지금 파일 이름(확장자 뺀)` 이면 **끝내지 않고 다시 청킹 · 임베딩**으로 넘어간다 → op `"retitled"`.
  - 다시 만들기는 지금의 "새 버전 만들기 → 교체" 길을 그대로 쓴다(옛 버전은 교체 직전까지 검색됨).
  - `reuse_vectors` 는 청크 해시가 같은 것만 다시 쓰므로 접두가 바뀐 청크는 새로 임베딩된다(정확).
- 흐름이 자연스럽게 이어진다:
  ```
  index-doc(새 경로)
    prev 없음 → moved_from → move_doc            (즉시: 경로 · 이름 · 메타 반영, 옛 벡터로 검색 계속)
    → 같은 호출 안에서 sync_doc_with 를 한 번 더(prev 있음, 해시 같음, chunk_title 다름) → retitled
  ```
  - `move_doc` 뒤 바로 이어 부르는 것은 `sync_doc_with` 안에서 처리(호출자는 고칠 것 없음).

### 3-3. 벡터 빈틈 막기 — 제목 갱신은 미루지 않는다

- `retitled` 다시 만들기는 `defer_over` 를 **무시하고 바로 임베딩**한다. 다 만든 뒤 교체하므로 그 문서는 끝까지 옛 벡터로 검색된다.
- 큰 문서는 그 자리에서 수 초~수십 초가 걸려 다른 자동 인덱싱을 막을 수 있다:
  - 청크 수 ≤ **`index.retitle_now_max`(기본 300청크)** → 바로 다시 만든다.
  - 넘으면 이동만 하고 `title_stale: true` 를 남긴다 → **쉬는 동안** `fill_pending` 단계 뒤에 한 건씩 다시 만든다(같은 "만든 뒤 교체", 미룸 없음).
  - 앱이 꺼져도 표시는 상태 파일에 남아 다음 실행 때 이어서 한다.
- 일괄 이름 바꿈(300건 × 18청크 ≈ 5,400청크 ≈ 2분): 이동은 즉시 끝나고, 다시 임베딩은 문서마다 이어서 진행. 진행 표시는 지금 `index-doc` 진행 그대로("반영 n/m").
  - 한 라운드에서 `retitled` 로 새로 임베딩할 청크 합이 `retitle_now_max × 4` 를 넘으면 나머지는 `title_stale` 로 넘겨 쉬는 동안 처리(앱을 오래 붙잡지 않게).

### 3-4. 바뀌는 것 · 안 바뀌는 것

| 항목 | 이름 바꿈 직후 | 제목 갱신 뒤 |
|---|---|---|
| 탐색기 모드 이름 찾기 · 메타(`meta.sqlite`) | 새 이름 | 새 이름 |
| 결과 표시(payload `doc_name` · 경로) | 새 이름 | 새 이름 |
| 채팅 검색 벡터 · BM25 청크 글 | 옛 제목 접두 | 새 제목 접두 |
| 삭제 안전장치 · 새 문서 허락 대기 | 걸리지 않음 | — |

### 3-5. 로그 · 요약

- 워커 로그: `[이동] 옛 → 새` 다음 줄에 `[제목 갱신] 새이름 n청크 (다시 씀 k)` 또는 `[제목 갱신 미룸] 새이름 n청크`.
- `@index-summary` 에 `"retitled"` · `"retitle_deferred"` 수를 더한다. 앱 로그 "대조 결과 …: 이동 n" 은 그대로.

## 5. 시험

1. 단위 시험(Rust `indexer` · Python 각각)
   - 이름만 바꿈 → `moved` 1건, 삭제 0건, 이어서 `retitled`, 청크 글 접두가 새 제목.
   - 이름 + 내용 바꿈 → 지금처럼 삭제 + 새 문서.
   - 같은 내용 파일 둘 중 하나 이름 바꿈 · 둘 다 바꿈 → 짝짓기 우선순위(같은 이름 → 같은 폴더).
   - 원본이 남은 채 다른 이름으로 복사 → `copied` + `retitled`.
   - 옛 상태 파일(`chunk_title` 없음) → 다시 인덱싱 없이 `same`.
2. 실측 재현(이번 측정 그대로): B 를 "이동 + 제목 갱신" 으로 바꿔 돌리면 A 와 같은 순위(이름형 @1 19/20)가 나와야 한다.
3. 일괄 이름 바꿈: 분류함 사본 300건 앞에 날짜를 붙임 → 허락 대기 · 삭제 안전장치 알림 없음, 이동 300 · 제목 갱신 진행, 끝까지 검색 결과가 비지 않음.
4. 큰 문서(>300청크) 이름 바꿈 → `title_stale` 로 미뤄지고 쉬는 동안 갱신.

## 6. 범위 밖 · 나중에

- 본문 추출 실패 문서(`failed`)는 이동 짝짓기 대상이 아니라 폴더 · 이름이 바뀌면 다시 추출을 시도한다(지금 128건). `failed` 항목에도 `content_hash` 를 남겨 같은 규칙으로 옮기면 풀린다 — 이번에 같이 할지 구현 때 정한다.
- 채팅 검색에 파일 이름(메타)을 따로 신호로 넣는 방안 — 이번 실측에서 제목 접두만으로 충분히 효과가 있어 보류.

## 7. 구현 메모 (2026-11-10)

- 설계와 다르게 한 것
  - 상한은 config.yaml 키 대신 환경변수 `SIMPLERAG_RETITLE_NOW_MAX`(기본 300청크)로 둠.
  - §3-3 의 "한 라운드 합계 상한(× 4)" 은 넣지 않음 — 문서 하나씩 `index-doc` 으로 오고, 보통 문서는 1건 0.3초라 필요가 작다.
  - Python 판은 벡터를 미루지 않으므로 `title_stale` 없이 늘 바로 제목 갱신.
  - CLI `index` 는 미룬 제목 갱신(`title_stale`)을 그 실행 끝에 모두 처리(`retitle_stale`).
- 결과 이름: `retitled`(이동 · 복사 뒤 제목 갱신까지 끝남), `moved` + `retitle_later`(큰 문서 — 쉬는 동안 `/embed-pending` 이 `retitle` · `retitled` 로 보고).
- 확인

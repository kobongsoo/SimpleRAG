해석

'첫 글자 16초'는 보통 말하는 TTFT(모델이 첫 토큰을 내는 시간)가 아니다. 화면 기준이라 ① 검색 단계와 ② LLM 의 첫 토큰 시간을 더한 값이고, 문항별로 ①+② 가 화면 첫 글자와 거의 정확히 맞는다(앱은 답변 요청 순간부터 시계를 재므로 ① 은 앱 TTFT 에 안 들어간다). 문서 질문 한 건에 LLM 을 세 번(검색어 만들기 → 발췌 판정 → 답변) 부른다. ② 가 긴 이유는 모델이 느려서가 아니라 약 2천 토큰(추정 — 단독 벤치 TTFT 와 맞는 크기) 프롬프트를 내장 GPU(Iris Xe)로 읽는 속도가 1.7B 약 204 tok/s · 4B 약 76 tok/s 이기 때문이다 — 모델 단독으로 재도 9.2초 · 24.4초로 앱 값과 같다(30토큰 짧은 프롬프트면 0.3초 · 0.8초). 외장 GPU 라면 같은 프롬프트를 1초 안팎에 읽을 수준이라, 이 지연은 대부분 하드웨어 한계다. 높음은 다른 GPU 작업과 겹친 영향도 일부 섞여 있다.

발견

검색 단계가 약 10초에서 잘린다 — 높음 80/100건, 중간도 19/100건이 9.9~10.4초에 몰렸다(10-20 측정 때 중간은 거의 없었음). 문서가 30개로 늘면서 1.7B 도 검색어 재작성·검색에 10초 제한을 자주 채운다.

해석

1) 유형이 어려울수록 떨어진다 — 싱글홉 > 멀티홉 > 추론. Faithfulness 는 중간 0.78 → 0.64 → 0.56, 높음 0.90 → 0.80 → 0.75. 멀티홉은 Context Recall 이 크게 낮고(중간 0.63) 핵심어를 모두 담은 답이 22~34% 뿐이라, 여러 곳의 정보를 다 모으지 못한다. 추론은 근거를 찾아도 규정을 사례에 적용하는 단계에서 근거 밖 내용을 덧붙이는 경우가 많다.

2) 이번에는 높음(4B)이 분명히 낫다. Faithfulness +0.15, Context Precision +0.12, Context Recall +0.09(전체, 95% 구간이 모두 0 위). 특히 추론에서 차이가 크다(Faithfulness +0.19). 정답 쪽 적중도 75% → 85% 로 높은데, 4B 가 검색어를 더 잘 다시 쓰는 덕으로 보인다(같은 검색 엔진, 검색어만 다름). 10-20(문서 1개)에서는 두 티어 차이가 거의 없었다.

3) Answer Relevancy 만 높음이 약간 낮다(0.67 vs 0.70, 차이 불분명). 높음은 "문서에서 확인할 수 없습니다"처럼 회피형 답이 9건(중간 1건)이라 그 문항이 0점이 됐다 — 근거가 모자랄 때 지어내지 않고 멈추는 쪽이라 Faithfulness 에는 오히려 유리하다.

판정자(Claude)는 Newploy 의 Qwen 계열과 다른 모델이라 자기 계열 편향은 없지만, 사람 판정과 맞춰 본 검증은 하지 않았다. Answer Relevancy 를 판정자 유사도로 바꿔 RAGAS 원래(임베딩 코사인)보다 엄격하게 나온다(10-20 의 0.8대 → 이번 0.7 안팎). 절대값보다 유형 간 · 티어 간 상대 비교와 규칙 지표(정답 쪽 · 핵심어)를 함께 볼 것.

버그

근거 페이지 번호 1쪽 밀림 — 30문서에서도 그대로. 이번 중간 티어 근거 212건 전부 화면 라벨이 내부 키보다 1 크다(예: 키 …:7 → 라벨 취업규칙 p.8).

지연

검색 단계 10초 제한 — 높음 80/100건, 중간 19/100건. 문서가 늘수록 중간 티어도 걸린다.

검색

문서가 늘어도 '문서'는 찾지만 '쪽'은 놓친다. 정답 문서 포함 92~96% 에 비해 정답 쪽 포함은 75~85%. 품목보고서처럼 뷰어 모드로 들어간 문서는 표·그림 영역 구분 없이 글자 길이로만 청크가 끊겨, 숫자가 든 표 쪽을 자주 놓친다. 정답이 두 문서에 걸친 문항 4건 중 중간 티어는 1건만 두 문서를 다 찾았다(높음 4건).

지연

긴 꼬리 — 높음은 200초를 넘긴 문항이 여러 건이고, 측정 스크립트의 300초 제한에 걸린 문항이 2건(C25 · D02, 다시 재서 채움)이다. 앱은 답변 생성 중 '새 대화' 버튼을 잠그므로 사용자는 답이 끝날 때까지 다른 질문을 못 한다. 다른 GPU 작업과 겹친 영향이 크지만, 16GB 내장 GPU PC 에서 4B 는 여유가 거의 없다는 뜻이기도 하다.

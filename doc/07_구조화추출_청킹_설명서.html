1. 한눈에 보기

인덱싱하거나 채팅에 파일을 첨부하면 모든 문서가 같은 길을 지납니다. 구조 파서가 맡는 형식이면 "이건 2단계 제목, 이건 표, 이건 3쪽"이라는 정보가 붙은 블록 목록이 만들어지고, 그 구조를 따라 청크를 자릅니다. 구조 파서가 없거나 실패하면 예전 평문 추출기(legacy)로 넘어갑니다.

2. 블록 JSON 뽑아 보기

"추출이 이 문서를 어떻게 나눴나"를 눈으로 확인하는 방법은 두 가지입니다. 결과 파일은 같은 모양의 <파일명>.blocks.json입니다.

방법 1 · 문서 한 건만 바로 보기 (권장)

인덱스와 설정을 건드리지 않습니다. 설정의 extract.engine 값과 상관없이 구조 파서로 돌리고, 블록 · 절 · 청크 요약을 화면에 보여 줍니다.

"C:\Users\bong9\AppData\Local\Programs\MoAISearch\simplerag-rs.exe" extract --blocks "D:\문서\출장여비규정.doc" --dump "D:\Temp\blocks_dump"
  • --dump <폴더>: 그 폴더에 파일 두 개를 저장합니다. 빼면 화면 출력만 합니다.
    • <파일명>.blocks.json: 후처리까지 끝난 블록 목록(5절)
    • <파일명>.chunks.json: 실제로 잘린 청크 목록(2026-11-11 추가). 맨 위에 이 청크를 만든 설정(chunk_tokens · chunk_overlap · chunk_mode)과 개수가 있고, 청크마다 no · tokens · section_id · path · source · page · page_from · page_to · text가 들어 있습니다. text는 접두 [문서 > 절]을 포함한 글로, 임베딩 · 검색 · LLM에 실제로 들어가는 글 그대로입니다. 청크 크기를 바꿔 가며 비교할 때 이 파일을 나란히 열어 보면 됩니다
  • Python 소스로 실행할 때는 src 폴더에서 python -m simplerag.cli extract --blocks <파일> --dump <폴더>로 같은 일을 합니다.

방법 2 · 인덱싱할 때마다 저장하기

데이터 폴더의 config.yaml(설치본은 C:\Users\bong9\AppData\Local\Programs\MoAISearch\config.yaml)에서 extract: 아래에 한 줄을 넣습니다.

extract:
  engine: blocks
  dump_blocks: true      # 인덱싱한 문서마다 blocks.json 저장 (기본 false)
항목내용
저장 위치데이터 루트의 blocks_dump\. 데이터 루트는 환경변수 SIMPLERAG_HOME, 없으면 exe가 있는 폴더(소스 실행은 프로젝트 루트)
적용 시점앱을 다시 시작한 뒤 새로 추출되는 문서만 저장됩니다. 내용이 바뀌지 않아 건너뛴 문서는 저장되지 않습니다
저장 시점후처리가 끝난 Document를 청크로 자르기 직전에 저장합니다. 그래서 절 묶기 · 청크 결과는 들어 있지 않고, 블록의 path도 비어 있습니다(절 묶기가 채우는 값)
실패해도파일을 쓰지 못해도 인덱싱은 계속합니다
진단이 끝나면 dump_blocks: false로 돌려 두세요. 문서 수만큼 JSON이 쌓입니다. 이 설정은 추출 결과를 바꾸지 않으므로 다시 인덱싱할 필요는 없습니다.

3. 1단계 · 파서 고르기

확장자로 파서를 고르고, 파일 앞 몇 바이트(매직)로 진짜 그 형식인지 확인합니다. 파서 모듈은 그 형식을 처음 만났을 때만 불러옵니다.

확장자파서파일 머리 확인
.docxooxml_docxZIP PK\x03\x04
.pptxooxml_pptxZIP
.xlsx · .xlsmooxml_xlsxZIP
.hwpxhwpxZIP
.docdoc_binOLE D0 CF 11 E0 A1 B1 1A E1
.pdfpdf%PDF
.html · .htm · .md · .markdown · .ipynbhtml_md확인 안 함(텍스트)

legacy로 가는 경우

  • 구조 파서가 없는 형식: hwp · xls · ppt · txt · 소스 코드 등
  • 파일 머리가 다른 경우: 이름만 .docx인 옛 .doc, 이름만 .doc인 RTF · HTML 등. 경고 "확장자는 .docx 이지만 파일 머리가 다름 → 기존 추출"을 남깁니다
  • 파서가 예외를 낸 경우: 깨진 파일, 글자층이 없는 스캔 PDF, PAPX를 못 읽는 DOC 등. 경고 "구조 파서 실패 → 기존 추출: …"을 남깁니다
  • 후처리의 무손실 검사에 걸린 경우(3단계 5번)

legacy 결과는 format: "legacy", raw_text에 평문이 담긴 Document가 됩니다. 이후 청킹도 예전 split_structured를 그대로 타기 때문에 legacy 엔진으로 인덱싱했을 때와 같은 청크가 나옵니다. 한 문서가 실패해도 인덱싱 전체는 멈추지 않습니다.

4. 2단계 · 형식별 파서가 블록을 만든다

기존 추출기는 글자만 모으고 버리던 구조 정보를, 파일 안에 들어 있는 그대로 읽는 것이 핵심입니다.

형식제목표그 밖
docx문단 스타일의 개요 수준(outlineLvl) 또는 스타일 이름("Heading N" · "제목 N" · "개요 N"). basedOn 상속까지 따라감<w:tbl> → 행렬. 가로 병합(gridSpan) · 세로 병합(vMerge) 펼침. tblHeader 행 = 머리글번호 목록 → list_item. TOC 스타일 · 목차 부품 → toc. header/footer.xml → 제외. 각주 → note. 텍스트상자 문단은 따로 블록
hwpx문단 모양의 heading type="OUTLINE" level=n → 수준 n+1<hp:tbl> → 칸 주소 · 병합 반영. header="1" 칸 = 머리글NUMBER/BULLET → 목록. 글상자 · 도형 속 문단 → 본문. 머리말 · 꼬리말 → 제외. 각주 · 미주 → note
doc문단 속성(PAPX)의 스타일 번호(sti 1~9 = 제목 1~9) · 개요 수준표 안 여부 · 행 끝 표시로 행렬 구성. 머리글 행 표시 읽음. 세로 병합은 아직 못 읽음(빈칸)본문 · 각주 · 머리말 · 글상자 영역 구분. 필드는 명령문은 버리고 결과만
pptx제목 자리표시자 = 수준 1. 제목 없는 슬라이드는 합성 제목 "슬라이드 N"(synthetic, 본문에는 안 넣음)<a:tbl> → 병합 펼침, 첫 행을 머리글로 추정슬라이드가 곧 절. 들여쓰기 수준 > 0 → 목록. 슬라이드 번호 · 날짜 · 바닥글 → 제외. 발표자 노트 → 문서 끝 '발표자 노트' 절
xlsx시트 이름시트 내용이 곧 표. 셀 주소로 위치를 맞추고(빈 칸 때문에 열이 밀리지 않게), 병합 펼침. 모든 행이 빈 열을 경계로 옆에 붙은 표를 나눔표 위의 "한 칸만 찬 행"(시트 제목 · 단위)은 문단으로 뗌. 날짜 숫자 → YYYY-MM-DD. 셀 메모 → note
pdf파일에 제목 표시가 없음. 기본은 후처리의 정규식 제목 폴백만 씀. extract.pdf_headings: true면 본문보다 확연히 큰 짧은 줄을 제목으로 추정(source=inferred)구조 표는 만들지 않음(줄 단위)쪽마다 읽어 page를 붙임. 여러 쪽의 맨 위 · 아래에 되풀이되는 줄 → header/footer. "12" · "- 12 -" · "3 / 30" → page_number. 한 줄 = 블록 하나. 글자층이 없으면(스캔) 예외 → legacy
html · md · ipynbh1~h6 · #table(th = 머리글, colspan/rowspan) · 파이프 표script · style · nav 등은 버리거나 제외. ``` → code 블록. 노트북 출력(outputs)은 제외

5. 블록 모델: blocks.json의 각 항목

모든 파서는 같은 그릇(Document · Block)에 결과를 담습니다. 그래서 형식이 늘어도 청킹 코드는 하나로 유지됩니다. blocks.json에는 기본값인 필드는 빠져 있습니다. 예를 들어 source가 없으면 parser, level이 없으면 0입니다.

6. 블록 종류는 어떻게 정하나

원리는 하나입니다. 파일이 구조를 표시해 두었으면 그 표시를 그대로 읽고, 표시가 없으면 위치와 되풀이로 추측합니다. docx · hwpx · doc · pptx · xlsx · html · md는 앞쪽에, PDF는 뒤쪽에 해당합니다. 그다음 공통 후처리가 일부 종류를 다시 고칩니다.

용어 주의: 블록 종류의 header는 쪽 맨 위에 찍히는 머리말입니다. 표의 머리글 행은 표 블록 안의 header_rows 값으로 따로 다룹니다(6-4).

6-1. 구조 표시가 있는 형식: 표 · 머리말 · 각주

파일 안의 XML 요소나, 글이 들어 있는 영역 · 파일로 정합니다. 글자 내용으로 추측하지 않습니다. 예를 들어 docx는 본문(<w:body>)을 돌면서 자식이 p면 문단으로, tbl이면 표로 보냅니다. 머리말은 애초에 다른 파일(header1.xml)에 있으므로, 그 파일에서 나온 문단은 모두 header가 됩니다.

hwpx<hp:tbl><hp:header> · <hp:footer> 컨트롤footNote · endNote
doc문단 속성의 "표 안" 표시(sprmPFInTable)와 행 끝 표시(sprmPFTtp)FIB의 머리말 영역 글자 범위각주 영역 범위

md파이프 표 줄——

6-2. 구조 표시가 있는 형식: 문단이 heading · list_item · paragraph 중 무엇인가

문단 스타일과 번호 매기기 속성으로 정합니다. docx의 판정 순서입니다(ooxml_docx.py _paragraph). 앞에서 걸리면 그 종류로 끝납니다.

순서종류조건
1toc목차 문서부품(sdt) 안의 문단이거나, 스타일 이름이 TOC N · 목차 N
2heading · 문단에 개요 수준(outlineLvl 0~8)을 직접 지정함 → 수준 n+1
· 스타일 이름이 Heading N · 제목 N · 개요 N → 수준 N
· 스타일에 개요 수준이 있음. 스타일 상속(basedOn)을 최대 10단계까지 따라 올라가며 찾고, 수준 9는 "본문"이라는 뜻이라 제외
3caption스타일 이름이 Caption · 캡션
4list_item번호 매기기 속성(numPr)이 있음. 깊이 = ilvl + 1
5paragraph위 어디에도 해당하지 않음

다른 형식도 같은 생각입니다.

형식headinglist_item
hwpxheader.xml의 문단 모양에 heading type="OUTLINE" level=n → 수준 n+1같은 자리의 type="NUMBER" · "BULLET"(문단 번호 · 글머리표)
doc스타일 번호 sti 1~9 = 제목 1~9, 문단의 개요 수준(sprmPOutLvl). sti 19~27은 toc목록 속성(sprmPIlfo · sprmPIlvl)
pptx제목 자리표시자(type="title" · "ctrTitle") = 수준 1. 제목 없는 슬라이드는 합성 제목 "슬라이드 N"(synthetic)들여쓰기 수준(lvl) > 0
xlsx시트 이름. 표 위의 한 칸만 찬 행(시트 제목 · 단위)은 paragraph로 뗌—
html · mdh1~h6 · #li · 목록 기호 줄

6-3. 구조 표시가 없는 형식: PDF

PDF에는 "제목"이나 "머리말"이라는 표시가 없고 쪽마다 글자 줄만 있습니다. 그래서 모든 줄을 일단 paragraph로 두고(한 줄 = 블록 하나), 쪽 가장자리 줄만 위치와 되풀이로 다시 판정합니다(pdf.py).

종류판정
page_number쪽 맨 위 · 아래 2줄(빈 줄 제외) 가운데 12 · - 12 - · 3 / 30 · Page 3 꼴인 줄
header · footer쪽 맨 위 · 아래 2줄에서 숫자를 #로 바꿔 비교합니다. 같은 글이 3쪽 이상 같은 가장자리에 되풀이되면 머리말(위) · 꼬리말(아래)로 봅니다. "Ⅰ. 적용대상 11"과 "Ⅰ. 적용대상 12"가 같은 줄로 묶입니다. 60자보다 긴 줄(본문 문장)과 숫자 · 기호를 빼면 4글자 미만인 줄은 후보에서 뺍니다. 처음 1개는 본문에 남깁니다
heading기본은 만들지 않고 후처리의 정규식 제목 폴백(6-5)에 맡깁니다. extract.pdf_headings: true일 때만 본문보다 확연히(12% 이상) 큰 짧은 줄을 제목으로 추정합니다(source=inferred, 크기 순위 = 수준). 굵기만으로는 정하지 않습니다
table만들지 않습니다. 표도 줄 단위 문단으로 나옵니다
(스캔 PDF)문서 전체 글자가 20자 미만이면 글자층이 없다고 보고 예외를 내 legacy(사이냅 폴백)로 보냅니다

6-4. 표의 머리글 행 (header_rows)

tables.py의 header_rows가 정합니다. 이 값은 청킹에서 "표가 잘린 조각에 머리글 행 다시 붙이기"에 쓰입니다.

  1. 파일이 표시한 경우 그 값을 씁니다. docx는 tblHeader 행, hwpx는 header="1" 칸으로 이뤄진 행, doc은 sprmTTableHeader, html은 th입니다. 다만 표 전체가 머리글로 표시된 양식 표는 머리글이 없는 것으로 봅니다.
  2. 표시가 없으면 첫 행을 보고 추정합니다. 이름이 든 칸이 2개 이상이고 숫자만 든 칸(금액 · 일수 · 날짜)이 하나도 없으면 머리글 1행으로 봅니다. pptx · xlsx는 이 방식으로 추정합니다.
  3. 판단이 서지 않으면 0으로 둡니다. 값이 든 행을 머리글로 잘못 잡으면, 표가 잘린 조각마다 엉뚱한 이름표가 다시 붙기 때문입니다.

6-5. 공통 후처리에서 종류가 다시 바뀌는 경우

파서가 정한 종류를 후처리(7절)가 고칠 때가 있습니다.

바뀜조건
paragraph → toc점선 · 가운데점 리더 뒤에 쪽번호로 끝나는 줄(제1장 총칙 ····· 3)이 3줄 이상 연달아 나올 때
table → paragraph칸이 하나뿐인 표. 보도자료 요약 상자처럼 표를 글상자로 쓴 경우
paragraph → heading (source=regex)파일이 알려 준 제목이 3개 미만일 때 정규식으로 찾습니다. 규칙은 조문 제N조(…) · 마크다운 # · 번호절 1.2 … 셋 중 하나로 고르고 섞지 않습니다. 이때 파서가 찾은 제목 몇 개는 문단으로 내립니다. 별표 · 부칙 같은 부속서 표지가 있으면 그것을 수준 1로 두고 조문을 한 단계 내립니다. pptx · xlsx는 슬라이드 · 시트가 곧 절이라 하지 않습니다

국내 문서는 제목을 스타일 대신 "굵게 · 크게"로 직접 꾸미는 일이 많습니다. 그래서 10절의 의료비 규정 docx도 제목 10개가 모두 heading/regex로 나왔습니다.

7. 3단계 · 공통 후처리

postprocess.finalize가 모든 형식에 같은 다섯 단계를 차례로 적용합니다. 글자를 지우지 않고 표시만 하는 것이 원칙입니다.

순서단계하는 일
1정제블록 글자와 표 셀마다 sanitize를 겁니다. 비문자 · 짝 없는 서로게이트처럼 토크나이저를 죽이는 문자를 지웁니다
2표 정리한 칸짜리 표(보도자료 요약 상자 같은 글상자)는 문단으로 되돌리고, 나머지는 셀을 한 줄로 다듬어 | a | b |로 그립니다. 머리글 행 수를 확정합니다. doc만 한 칸에 여러 행을 줄바꿈으로 눕혀 넣은 표를 행으로 펼칩니다(docx · hwpx는 긴 설명 칸이 많아 잘못 펼칠 위험이 큼)
3목차 표시"제1장 총칙 ······ 3"처럼 점선 리더 뒤에 쪽번호로 끝나는 줄이 3줄 이상 이어지면 toc로 표시합니다. 목차가 근거로 끌려오는 문제를 막습니다
4제목 폴백파일이 알려 준 제목이 3개 미만이면 "제N조", "1.2" 같은 정규식으로 제목을 추측합니다(source=regex). 국내 문서는 스타일 대신 굵게 · 크게로 제목을 만드는 일이 흔하기 때문입니다. pptx · xlsx는 슬라이드 · 시트가 곧 절이라 하지 않습니다
5무손실 검사제외 블록을 뺀 본문이 전체의 70% 미만이면 무언가 잘못 표시된 것으로 보고 평문 폴백으로 돌립니다(경고를 남김)

8. 4단계 · 절로 묶기

assemble.build_sections는 블록을 읽기 순서대로 돌면서 "제목 경로 스택"을 쌓습니다. 여기서는 어디까지가 한 절인가만 정하고, 자르는 일은 다음 단계가 합니다.

제목 경로 스택 = []
heading(level=n) → 스택을 n-1 깊이까지 줄이고 이 제목을 넣는다 → 새 절 시작
그 밖의 블록      → 현재 절에 추가, block.path = 스택 복사
제외 블록         → 절에 넣지 않음

예) 제3장 근무 (L1) > 제12조(근로시간) (L2) > 본문 · 표 …
    → 절 path = ["제3장 근무", "제12조(근로시간)"]

첫 제목이 나오기 전의 블록은 "머리말 절"(path 없음)이 됩니다. 절마다 id(문서 안 번호, payload의 section_id)와 걸친 쪽 범위(page_from · page_to)가 붙습니다.

9. 5단계 · 청크 자르기

chunk.split_blocks는 정규식으로 추측한 절 대신 파일이 알려 준 절 · 블록 · 표 행을 경계로 씁니다. 예산은 chunk.tokens(기본 128, e5 토크나이저 기준, 접두 포함)입니다.

  1. 폴백 문서(raw_text)는 예전 split_structured를 그대로 부릅니다.
  2. 절이 예산 안이면 앞의 작은 절들과 묶습니다. 이때는 겹침이 없습니다.
  3. 절이 예산을 넘으면 모아 둔 것을 먼저 내보내고 "단위" 경계에서 끊습니다. 단위는 블록 하나이고, 표는 행 하나입니다.
  4. 단위 하나가 예산을 넘으면 그 안에서만 줄 → 문장 → 토큰 순으로 쪼갭니다. 이때만 chunk.overlap(16토큰)만큼 겹칩니다. chunk.overflow_ratio(기본 1.0 = 끔)를 높이면 약간 넘는 단위는 쪼개지 않고 통째로 둡니다.
  5. 표 행으로 시작하는 조각에는 그 표의 머리글 행을 다시 붙입니다. 머리글이 chunk.table_header_max_tokens(64)를 넘으면 붙이지 않습니다.
  6. 제목만 든 청크를 만들지 않습니다(2026-11-11 추가). 다음 두 경우 모두 제목을 다음 조각 맨 앞에 함께 담습니다. 그 조각은 제목 토큰만큼 예산을 조금 넘을 수 있고, 표본 46건에서 최대 166토큰이었습니다.
    • 절 안: 조각에 절 제목(과 바로 뒤의 표 머리글)만 들었는데 다음 단위가 예산을 넘는 경우. 예: "제5조(의료비 지원 예외 항목)" 바로 뒤에 긴 문단이 오는 경우
    • 절 사이: 본문 없는 상위 제목 절(예: "4. 지급기준" 바로 뒤에 "4.1.")이 큰 하위 절 앞에서 홀로 남는 경우. 바로 뒤 절의 상위 제목일 때만 넘깁니다. "3.2 '회원'이라 함은 …"처럼 제목 줄이 곧 내용인 조항은 그대로 둡니다
  7. 접두 [문서명 > 상위 제목 > 절 제목] 한 줄을 붙입니다(80자를 넘으면 가운데부터 "…"로 줄임). 검색과 답변 생성 양쪽에 문맥을 줍니다.
  8. 안전장치: 어떤 청크도 chunk.hard_max(510, e5 입력 한계)를 넘지 않게 마지막에 자르고, chunk.min_tokens보다 짧은 꼬리 조각은 버립니다.

청크마다 메타가 붙어 Qdrant payload로 들어갑니다.

키뜻
text접두를 포함한 청크 글(임베딩에 넣는 글 그대로)
section_id대표 절(첫 절) 번호
path대표 절의 제목 경로
source제목 출처(parser · regex · inferred), 폴백 문서는 legacy
page_from · page_to · page청크가 걸친 쪽 범위와 시작 쪽. 출처 쪽 표시에 씀

10. 실제 예시

docx · 제목 스타일이 없는 규정 문서

sample/15.의료비 지원 규정_17.03.14.docx: 블록 42개(paragraph/parser 30 · heading/regex 10 · list_item/parser 2), 절 11개, 청크 16개입니다. 워드 스타일 제목이 없어서 후처리 4단계(제목 폴백)가 "제N조"를 제목으로 잡았습니다.

{ "format": "docx", "title": "15.의료비 지원 규정_17.03.14", "pages": null, "warnings": [], "raw_text": null,
  "blocks": [
    { "type": "paragraph", "text": "의료비 지원 규정" },
    { "type": "paragraph", "text": "2017.03.14 개정" },
    { "type": "heading", "text": "제1조(목적)", "level": 2, "source": "regex" },

    { "type": "heading", "text": "제2조(용어의 정의)", "level": 2, "source": "regex" },
    ... ] }

그 결과로 나온 청크 하나입니다.

meta: section_id=2, path=['제2조(용어의 정의)'], source='regex'
[15.의료비 지원 규정_17.03.14 > 제2조(용어의 정의)]

본 규정에서 임직원이라 함은 임원, 정규직 사원을 말한다.

청크 0은 작은 절 두 개(머리말 절 + 제1조)를 예산 안에서 묶은 경우입니다. 절마다 자기 접두가 붙어 있습니다.

sample/25.출장여비규정_16.04.01.doc의 "1.2 정의" 절에 있는 용어 표입니다. 블록 JSON에서는 표 하나입니다.

1. 한눈에 보기 — 정말 자동으로 보이나?

네, 앱을 고치지 않아도 보입니다. 다만 두 가지를 모두 올려야 합니다.

올릴 것어디로하는 일
모델 설치 파일
MoAISearch_Model_<별칭>_r<판>.exe (+ -1.bin, -2.bin)		GitHub 릴리스 models-1
(kobongsoo/MoAI-S)		앱의 [받기] 가 실제로 받아 설치하는 파일

① 목록에 모델 항목 적기→ ② build_model_installers.py→ ③ 릴리스 models-1 에 설치 파일→ ④ docs/models.json 푸시→ ⑤ 사용자 설정 > 모델에 나타남

앱이 목록을 읽는 방식 (이걸 알면 "왜 안 보이지?" 가 풀립니다)

  • 앱은 설정 > 모델 탭을 열 때 배포 사이트의 models.json 을 받아 %LOCALAPPDATA%\MoAISearch\models_catalog.json 에 저장합니다.
  • 저장한 지 하루(24시간)가 안 됐으면 다시 받지 않습니다. 그래서 사용자 PC 에는 최대 하루 늦게 보일 수 있습니다.
  • 받은 목록과 앱에 든 목록 중 updated 날짜가 더 늦은 쪽을 씁니다. 빌드 스크립트가 날짜를 오늘로 고쳐 줍니다.
  • 목록 안에서 status 가 ready 이고, min_app 이 사용자 앱 판 이하일 때만 [받기] 가 됩니다. hidden 은 아예 안 보입니다.
앱을 고쳐야 하는 경우는 하나뿐입니다. 모델의 대화 형식(format)이 앱이 아는 것이 아닐 때입니다. 지금 아는 형식: qwen3 · midm · kanana · lfm2 · llama3. 이 밖의 형식(예: Gemma, Phi)이거나 llama.cpp 가 모르는 구조(예: Kanana 2 1.3B 의 kanana2tiny)면 앱 새 판이 필요합니다.

3. 예시 A — 새 모델 넣기 (처음부터 끝까지)

예시: "Exa-2B" 라는 가상 모델(파일 Exa-2B-Q4_K_M.gguf, 대화 형식 llama3, Apache-2.0)을 기본(3B 이하) 모델로 내놓는 경우입니다.

3-1. 모델 파일과 라이선스 글 두기

D:\Project\SimpleRAG\models\Exa-2B-Q4_K_M.gguf
D:\Project\SimpleRAG\licenses\models\Exa-2B-Apache-2.0.txt

라이선스 글 맨 위에 원본 주소 · GGUF 를 받은 곳 · 라이선스 이름을 몇 줄 적고, 그 아래 라이선스 전문을 붙입니다(Kanana-Nano-CC-BY-NC-4.0.txt 가 본보기).

3-2. 앱에 든 목록에 항목 더하기

rust\ragsearchbox\ui\models.json 의 "models" 배열에 아래 항목을 더합니다. 빌드 스크립트는 이 파일에 없는 별칭은 만들지 않습니다. 처음에는 "status": "hidden" 으로 두고 측정이 끝나면 ready 로 바꾸는 것을 권합니다.

{
  "alias": "exa-2b-q4",                 // 영문 소문자 · 숫자 · . - _ 만, 64자 이하
  "name": "Exa 2B",
  "vendor": "Example Lab",
  "tier": "base",                       // base = 기본(3B 이하), precise = 정밀(3B 이상)
  "params_b": 2.0,
  "file": "Exa-2B-Q4_K_M.gguf",
  "file_bytes": 0,                      // 빌드가 채움
  "format": "llama3",                   // qwen3 | midm | kanana | lfm2 | llama3
  "neighbors": false,
  "status": "ready",
  "rank": 5,                            // 같은 구분 안에서 작을수록 위 · 추천 우선
  "ttft_ratio": 1.3,                    // Qwen3-1.7B 대비 첫 글자 시간 배수(측정값)
  "korean": false,

  "icon": { "mono": "E", "color": "#2f7d6d" },

  "released": "2026",
  "languages": "한국어 포함 다국어",
  "intro": "상세보기 첫 문단 — 어떤 모델인지 두세 문장",
  "bench": { "date": "2026-11-20", "correct": 52, "of": 100, "ungrounded": null, "evasive": 1, "ttft_s": 3.3 },

  "license_note": "",
  "license_file": "Exa-2B-Apache-2.0.txt",  // licenses\models 안의 파일 이름
  "source_url": "https://huggingface.co/example/exa-2b-instruct",
  "parts": []                           // 빌드가 채움(조각 이름 · 크기 · SHA256)

(위 // 설명은 이해를 돕기 위한 것입니다. JSON 은 주석을 허용하지 않으니 실제 파일에는 넣지 마세요.)

3-3. (권장) 품질 · 속도 재기

ttft_ratio 와 bench 는 추천 순서와 상세보기에 쓰입니다. 골든 100문항으로 잽니다(측정 중엔 빌드 같은 무거운 작업을 같이 돌리지 않습니다).

.venv\Scripts\python bench\ragas_golden.py collect ...   # 답 모으기
.venv\Scripts\python bench\score_rule.py ...             # 핵심어 정답 수 · 첫 글자 시간

3-4. 설치 파일 만들기

cd D:\Project\SimpleRAG
.venv\Scripts\python rust\build_model_installers.py --only exa-2b-q4 --dry-run   # 원본을 찾는지만 보기
.venv\Scripts\python rust\build_model_installers.py --only exa-2b-q4             # 실제로 만들기

결과 (dist-rust\models-release\):

MoAISearch_Model_exa-2b-q4_r1.exe     ← 1.9GB 이하면 이것 하나
models.json                          ← Pages 에 올릴 목록(전체 목록 · parts · updated 채워짐)

스크립트는 rust\ragsearchbox\ui\models.json(앱에 든 사본)도 같이 고칩니다. 1.9GB 가 넘는 모델은 .exe + -1.bin + -2.bin … 로 나뉩니다(GitHub 첨부 한도 2GB).

3-5. GitHub 릴리스 models-1 에 설치 파일 올리기

cd D:\Project\SimpleRAG\dist-rust\models-release
gh release upload models-1 MoAISearch_Model_exa-2b-q4_r1.exe -R kobongsoo/MoAI-S
# 조각이 있으면 함께:  ... _r1.exe _r1-1.bin _r1-2.bin
순서를 지킵니다 — 설치 파일 먼저, 목록 나중. 목록부터 올리면 그 사이 [받기] 를 누른 사용자는 "배포 파일을 찾지 못했습니다" 를 봅니다.

3-6. 목록 파일을 Pages 에 올리기

copy D:\Project\SimpleRAG\dist-rust\models-release\models.json D:\Project\MoAI-S\docs\models.json
cd D:\Project\MoAI-S
git add docs/models.json
git commit -m "답변 모델 목록 — Exa 2B 더함"
git push

푸시 후 GitHub Pages 반영까지 보통 1~2분, 사이트 캐시까지 길면 10분쯤 걸립니다.

3-7. 소스 저장소에도 남기기

SimpleRAG 의 rust\ragsearchbox\ui\models.json 변경을 커밋해 둡니다. 다음 앱 판에 이 목록이 들어가, 인터넷이 막힌 곳에서도 목록이 보입니다.

끝. 0.1.4 이상 사용자가 설정 > 모델을 열면(목록을 받은 지 하루가 지났을 때) "Exa 2B" 가 보이고, [받기] → 확인(SHA256) → 설치 → [사용] 까지 앱이 합니다. 설치 파일이 모델 옆에 exa-2b-q4.model.json 을 두므로 워커도 새 별칭을 압니다.

4. 예시 B — 이미 있는 모델 고쳐 다시 내기

예: Qwen3.5-4B 를 더 나은 GGUF 로 바꾸는 경우. 판 번호를 올려 파일 이름이 겹치지 않게 합니다(옛 파일을 받는 중인 사용자가 깨지지 않습니다).

# 1) models\ 의 GGUF 를 새것으로 바꾸고 (파일 이름이 바뀌면 목록의 "file" 도 고침)
.venv\Scripts\python rust\build_model_installers.py --only qwen3.5-4b-q4 --rev 2

# 2) 설치 파일 올리기 (이 모델은 2.7GB 라 조각 3개)
cd dist-rust\models-release
gh release upload models-1 MoAISearch_Model_qwen3.5-4b-q4_r2.exe MoAISearch_Model_qwen3.5-4b-q4_r2-1.bin MoAISearch_Model_qwen3.5-4b-q4_r2-2.bin -R kobongsoo/MoAI-S

# 3) 목록 올리기 — 예시 A 의 3-6 과 같음

목록 글(소개 · 장단점 · 측정값)만 고칠 때는 설치 파일을 다시 만들 필요가 없습니다. rust\ragsearchbox\ui\models.json 을 고치고 updated 를 오늘 날짜로 바꾼 뒤, 그 파일을 docs\models.json 으로 복사해 푸시합니다.

같은 이름의 파일을 --clobber 로 덮어쓰지 마세요. 목록의 SHA256 과 달라져 받는 도중인 사용자는 확인 단계에서 실패합니다. 늘 --rev 를 올립니다.

5. 예시 C — 모델 숨기기 · 내리기

status목록에 보이나쓰는 때
ready모두에게 보이고 [받기] 가능내놓는 모델
hidden아무에게도 안 보임측정 전 · 탈락 (예: LFM2.5 — 정답 35)
retired이미 설치한 사람에게만 보임(새로 받기 불가)더 나은 모델로 바뀐 옛 모델 (예: Qwen3-4B)

값만 바꾸고 updated 를 오늘로 고쳐 docs\models.json 을 푸시하면 됩니다. 릴리스의 설치 파일은 지우지 않아도 됩니다.

7. 올린 뒤 확인하기

  1. 주소가 열리는지: 브라우저로 https://kobongsoo.github.io/MoAI-S/models.json 을 열어 새 항목과 updated 를 봅니다.
  2. 설치 파일이 받아지는지: 
    curl -sIL https://github.com/kobongsoo/MoAI-S/releases/download/models-1/MoAISearch_Model_exa-2b-q4_r1.exe
    마지막 응답이 200 이면 됩니다.
  3. 내 PC 앱에서 바로 보기: 하루 캐시 때문에 안 보이면 앱을 끄고 %LOCALAPPDATA%\MoAISearch\models_catalog.json 을 지운 뒤 다시 켜서 설정 > 모델을 엽니다.
  4. [받기] → 진행 막대 → "설치됨" → [사용] → 질문 하나 해서 답이 나오는지 봅니다. 모델이 안 뜨면 앱이 원래 모델로 되돌리고 알려 줍니다.

8. 자주 막히는 곳

증상까닭 · 해결
목록에 새 모델이 안 보임① 하루 캐시 — 7-3 처럼 캐시 지우기 ② status 가 hidden ③ updated 가 앱에 든 목록보다 이르거나 같음 ④ Pages 반영 전(몇 분 기다림)
보이는데 [받기] 가 회색min_app 이 사용자 앱 판보다 높음, 또는 parts 가 비어 있음(빌드 전 목록을 올림)
"배포 파일을 찾지 못했습니다"릴리스에 그 이름의 파일이 없음 — 목록의 parts[].name 과 올린 파일 이름 · --rev 확인
"받은 크기가 다릅니다" / "받은 파일이 손상되었습니다"올린 파일과 목록의 크기 · SHA256 이 다름 — 빌드 후 파일을 다시 만들었거나 덮어씀. 같은 빌드에서 나온 파일 · 목록을 함께 올림
[사용] 후 원래 모델로 되돌아감llama.cpp 가 그 모델을 못 읽음(모르는 구조) 또는 format 이 틀림 — 로그(설정 > 로그)의 "답변 모델 오류" 줄 확인
빌드: "라이선스 글이 없습니다"licenses\models\<license_file> 이 없음 — 이 폴더는 git 에 안 올라가므로 다른 PC 에서는 복사해 둠
빌드: "목록에 없는 별칭"3-2 처럼 rust\ragsearchbox\ui\models.json 에 항목을 먼저 적음
회사망에서 [받기] 가 막힘사용자가 릴리스 페이지에서 설치 파일(조각 포함, 같은 폴더)을 직접 받아 .exe 실행 — 설정 > 모델에 "설치됨" 으로 나타남

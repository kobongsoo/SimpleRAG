simplerag.exe 로 cmd 에서 질문·답변 테스트하기

트레이 앱(RAGSearchBox.exe) 없이, 명령 프롬프트(cmd)에서 simplerag.exe 를 직접 실행해 질문을 던지고 근거·답변·소요 시간을 확인하는 방법이다. 아래 출력 예시는 이 PC 의 dist\simplerag 배포본으로 실제 실행한 결과다.

대상: dist\simplerag\simplerag.exe (2026-10-22 빌드) · 인덱스 76문서 / 8,749청크 · Qwen3-1.7B · iGPU(Vulkan) · 리랭커 있음

1빠른 시작

cd /d D:\Project\SimpleRAG\dist\simplerag
simplerag.exe status
simplerag.exe ask "본인 결혼 시 경조금은 얼마인가요?"

여러 질문을 연달아 해 보려면 simplerag.exe chat — 모델을 한 번만 올려서 두 번째 질문부터 빠르다.

2준비 — 폴더와 주의점

항목내용
실행 위치simplerag.exe 가 있는 폴더에서 실행한다. exe 는 자기 폴더를 데이터 폴더로 쓴다 — qdrant_data(벡터 인덱스) · bm25_index.npz · index_state.json · config.yaml · models
RAGSearchBox트레이 앱이 같은 인덱스 폴더를 쓴다. 테스트 중 인덱스가 바뀌거나 파일이 잠기는 일을 피하려면 트레이 메뉴 종료로 끄고 테스트하는 것을 권한다.
인덱스질문 전에 인덱스가 있어야 한다. status 의 "문서 N건" 이 0 이면 먼저 index.
도움말simplerag.exe --help, 명령별로 simplerag.exe ask --help

7옵션 정리 (ask · chat)

옵션뜻예
--folder <폴더>(ask·search) 그 폴더(하위 포함) 문서만 근거로 쓴다ask "출장 일비는?" --folder "D:\Project\SimpleRAG\sample"
--model <이름>생성 모델 직접 지정: qwen3-0.6b-q4 · qwen3-1.7b-q4 · midm-2.0-mini-q4ask "…" --model qwen3-0.6b-q4
--precise정밀 모드(1.7B). 기본 모델은 config.yaml 의 설정을 따른다(지금 배포본은 1.7B)chat --precise
--top-k NLLM 에 넘길 근거 개수 (기본 3)ask "…" --top-k 5
--max-tokens N답변 최대 토큰 수ask "…" --max-tokens 300
--no-stream답변을 다 만든 뒤 한 번에 출력 — 콘솔에서 글자가 깨지거나 파일로 저장할 때ask "…" --no-stream > out.txt

그 밖의 명령: backend(CPU/iGPU 선택 근거, --reprobe 로 재측정) · warmup(예열 단계별 시간) · clear(인덱스 삭제 — 되돌릴 수 없다. 쓰는 법과 백업은 8-1).

8문서 넣기 — index · extract

rem 폴더의 바뀐 문서만 반영(증분)
simplerag.exe index --dir "D:\Project\SimpleRAG\sample_pdf"

rem 인덱싱 전에 추출이 잘 되는지 한 파일만 미리보기
simplerag.exe extract "D:\Project\SimpleRAG\sample_pdf\취업규칙.pdf" --chars 800
  • --rebuild 는 인덱스를 처음부터 다시 만든다 — 다른 폴더로 넣었던 문서까지 모두 사라진다.
  • 폴더에서 지워진 문서가 많으면(30% 또는 50건 이상) 안전장치로 삭제를 멈춘다. 정말 지운 것이면 --allow-delete.
  • 새 폴더를 추가로 넣으면 기존 인덱스에 더해진다(지금 배포본은 sample + sample_pdf = 76건).
인덱스를 바꾸기 전에 RAGSearchBox 를 끈다. 인덱스 폴더(qdrant_data)는 한 프로세스만 열 수 있다. 트레이 앱이 떠 있으면 index · clear 가 잠금 오류("already accessed")로 실패한다 — 트레이 메뉴 → 종료.

8-1. 기존 인덱스 제거 — clear

clear 는 데이터 폴더의 인덱스 세 가지(벡터 인덱스 qdrant_data · BM25 캐시 bm25_index.npz · 증분 상태 index_state.json)를 지운다. 모델·config.yaml·원본 문서는 건드리지 않는다.

rem 인덱스 전체 삭제 — 지울 목록을 보여 주고 [y/N] 로 한 번 더 묻는다
simplerag.exe clear

rem 묻지 않고 바로 삭제(스크립트용)
simplerag.exe clear -y

rem 문서 한 건만 인덱스에서 빼기 — 경로는 인덱싱할 때와 똑같아야 한다(status -v 로 확인)
simplerag.exe clear --doc "D:\Project\SimpleRAG\sample_pdf\15.의료비 지원 규정_17.03.14.pdf"
데이터 루트: D:\Project\SimpleRAG\dist\simplerag
문서 3건 / 다음 항목을 삭제합니다:
  벡터 인덱스            0.2 MB  qdrant_data
  BM25 캐시           0.0 MB  bm25_index.npz
  증분 상태             0.0 MB  index_state.json
  삭제: 벡터 인덱스
  삭제: BM25 캐시
  삭제: 증분 상태

삭제 완료. `index --dir <폴더>` 로 다시 인덱싱하세요.
  • 되돌릴 수 없다. 지금 인덱스를 남겨 두려면 먼저 세 항목을 다른 폴더로 복사해 둔다 (예: qdrant_data · bm25_index.npz · index_state.json → ..\backup_YYYYMMDD\). 되돌릴 때는 다시 복사해 넣으면 된다.
  • 삭제 뒤 status 는 0청크 · 문서 0건 · BM25캐시 없음 으로 나온다.
  • clear --doc 뒤에는 BM25 가 다음 index --dir 때 다시 만들어진다. 그 전에도 뺀 문서는 근거로 나오지 않는다.

8-2. 처음부터 폴더 지정해서 인덱싱

인덱스를 비우고 원하는 폴더만 새로 넣는다. 아래 두 방법은 결과가 같다.

rem 방법 A — 지우고 넣기(두 단계라 중간 상태를 확인할 수 있다)
simplerag.exe clear -y
simplerag.exe index --dir "D:\Project\SimpleRAG\sample_pdf"

rem 방법 B — 한 번에(기존 인덱스를 버리고 이 폴더로 새로 만든다)
simplerag.exe index --dir "D:\Project\SimpleRAG\sample_pdf" --rebuild

rem 하위 폴더는 빼고 그 폴더 바로 아래 문서만
simplerag.exe index --dir "D:\Project\SimpleRAG\sample_pdf" --no-recursive

rem 확인
simplerag.exe status
  [1/3] [추가] 03.경조사지원규정_12.01.01.pdf                         6청크  (2.2 문서/s, 남은시간 1s)
  [2/3] [추가] 15.의료비 지원 규정_17.03.14.pdf                      14청크  (1.0 문서/s, 남은시간 1s)
  [3/3] [추가] 07.동호회규정_11.06.01.pdf                          28청크  (0.7 문서/s, 남은시간 0s)

  • 폴더를 여러 개 넣으려면 index --dir 를 폴더마다 한 번씩 실행한다(--rebuild 는 첫 폴더에만).
  • 넣는 파일 형식: .pdf .doc .docx .ppt .pptx .xls .xlsx .hwp .hwpx .txt .md .html .htm 등. Office 임시 파일(~$…)은 건너뛴다.
  • @index-summary {…} 줄은 RAGSearchBox 가 읽는 기계용 요약이다. 사람은 마지막 "문서 N건 / 추가 …" 줄을 보면 된다.
  • RAGSearchBox 를 쓸 거라면 인덱싱한 폴더를 RAGSearchBox.ini 의 [Scope] Folders 에도 적는다. 범위 밖 문서는 트레이가 "지정 폴더 밖 문서 N건" 으로 알리고, 지금 인덱싱을 누르면 인덱스에서 뺀다.

8-3. 파일 하나만 지정해서 인덱싱

index 는 폴더(--dir)만 받는다. 파일 한 건은 chat 의 /index-doc 로 넣는다 — 기존 인덱스에 그 문서만 더하거나(이미 있으면 새 내용으로 바꾼다), clear 뒤에 하면 그 파일 하나짜리 인덱스가 된다.

simplerag.exe chat
질문> /index-doc D:\Project\SimpleRAG\sample_pdf\07.동호회규정_11.06.01.pdf
질문> /bm25
질문> /status
질문> exit
질문> @index {"op":"index-doc","ok":true,"path":"…\\07.동호회규정_11.06.01.pdf","result":"added","chunks":28,"ms":602}
질문> @index {"op":"bm25","ok":true,"chunks":28,...}
질문>   28청크 / 0.1MB
  • "ok":true · "result":"added"(새로 넣음) 또는 "modified"(바꿈)이면 성공이다. 실패하면 "ok":false 와 "why"(예: "파일이 없습니다").
  • /index-doc 뒤에 /bm25 를 꼭 한 번 실행한다. 안 하면 키워드 색인에 그 문서가 빠져 dense 검색으로만 찾는다 (status 에 "BM25캐시 : 없음" 으로 보인다). 여러 파일을 넣을 때는 /index-doc 를 다 한 뒤 마지막에 한 번.
  • 경로는 따옴표 없이 쓴다. 콘솔에서 직접 치면 한글 경로도 그대로 된다. 파이프로 넣을 때 한글이 깨지면 /index-doc {"path": "D:\\…\\파일.pdf"} 처럼 JSON 으로 쓴다.
  • chat 없이 하고 싶으면, 그 파일만 든 폴더를 만들어 index --dir <그 폴더> 를 써도 된다. 다만 나중에 그 폴더를 지우고 다른 폴더로 index 해도 이 문서는 인덱스에 남는다(clear --doc 로 뺀다).

"검색된 근거가 없습니다" / 관련 근거 없음인덱스에 그 문서가 없거나 질문이 문서와 동떨어졌다. status 로 문서 수 확인 → search 로 검색 결과 확인.
첫 질문이 느리다ask 는 매번 모델을 올린다(약 5~8초). 여러 질문은 chat 으로.
설정 경고가 먼저 나온다config.yaml 에 오타·범위 밖 값이 있다. 경고 문구대로 고치거나 status 의 설정파일 경로를 확인.

10테스트 체크리스트

  1. RAGSearchBox 종료 — 트레이 메뉴 → 종료
  2. status — 문서 수 · 생성모델 · 백엔드(iGPU/CPU) · 리랭커 "있음" 확인
  3. search "질문" — 정답 문서가 상위 3건에 들어오는지
  4. ask "질문" — 근거 · 답변 · 첫 글자/완료 시간 확인. 답의 사실은 근거 본문으로 검증
  5. chat — 질문 3~5개 연속. 두 번째부터 빨라지는지, /folder 한정 검색이 되는지
  6. 끝나면 exit → 필요하면 RAGSearchBox 다시 실행
